# Plan 130-03 — TUC-08 live UAT + TUC-09 confirmation + close-out

**Mode:** standard
**Goal:** Confirm the whole Tucson experience live and close the milestone. This plan authors the formal UAT checklist (D-06/D-07/D-08), has Chris run it against the live app and sign off (TUC-08), confirms the live tether icon matches the pre-determined verdict (TUC-09, D-09), then rolls everything up into `130-VERIFICATION.md` and flips the REQUIREMENTS.md traceability for TUC-07/08/09. Because the icicle/Money-In render path runs through the external `ev-accounts-api` service, the *visual* render is confirmed by a human here rather than machine-asserted (the DB data shape was proved correct in Phase 129 and independently re-derived in Plan 130-01).

**This plan is not autonomous** — it gates on Chris's live sign-off. The executor authors the checklist and the roll-up scaffolding, then pauses for the human UAT result before finalizing status and traceability.

<threat_model>
No new attack surface: this plan writes only planning/verification markdown + the REQUIREMENTS.md traceability table. No code, no DB writes, no service-role usage, no schema/RPC/frontend change. (The only "risk" is a false-positive sign-off — mitigated by the D-09 predict-then-confirm design and by requiring the machine gates in 130-01/130-02 to have passed before UAT.)
</threat_model>
