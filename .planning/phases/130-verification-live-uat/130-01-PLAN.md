# Plan 130-01 — TUC-07: blind re-derivation + source-chain audit + D-05 confirmation

**Mode:** standard
**Goal:** Prove every *displayed* Tucson figure is real and durably sourced by re-extracting it from the source ACFR PDFs along a second, fully independent path and diffing against live production — the higher bar over Phase 129's DB-vs-RECON re-sum. This plan delivers the machine-verifiable core of TUC-07: a from-scratch re-derivation harness, a full source-chain audit, and confirmation that the Phase-129 D-05 loader-hardening (CR-01/WR-01) is in place and still nets a residue-free idempotent re-run.

**D-05 status note (deviation from CONTEXT):** CONTEXT §D-05 frames CR-01/WR-01 as "fix both inline." Those fixes were already applied during Phase 129's code-review-fix cycle (commits 55f359a CR-01, 30aa388 WR-01) and are present in the current `scripts/processTucson.js`. This plan therefore **confirms** them (code inspection + `node --check` + idempotent smoke-run) rather than re-applying — re-applying would be a no-op and risks undoing the defense-in-depth municipality-keyed delete WR-01 chose. If inspection finds either fix absent or wrong, Task 130-01-04 escalates to applying it.

Analogs: `scripts/verify-phase124-rederive.mjs` (blind re-derivation harness: own `execFileSync('pdftotext', ['-table', pdf, '-'])` pass, exact-0 tolerance, read-only DB, no loader imports) and `scripts/verify-phase124-cohort-audit.mjs` (source-chain / invariant audit). Reuse their env-loading + `createClient` on the `treasury` schema pattern.

<threat_model>
**T-130-01 — Privileged idempotent re-run of the production loader during the D-05 smoke-check.**
- *Surface:* Task 130-01-04 re-invokes `scripts/processTucson.js` with the `SUPABASE_SERVICE_KEY` against the shared production `treasury.budgets` / `treasury.data_sources` tables.
- *Threats:* (a) a non-idempotent re-run mutating shipped figures; (b) leaving `data_sources` residue if the run aborts partway; (c) running against a wrong/expanded FY window.
- *Mitigations:* the re-run is expected to net **0 change** (the RPC's `(municipality_id, fiscal_year, dataset_type)` upsert + WR-01 pre-clear are idempotent); re-run the D-04 source-chain audit immediately after and require 0 residue + $0 delta; scope the smoke-check to the existing FY2015–FY2024 window only (no new FYs — scope fence). The re-derivation and audit scripts themselves are **read-only** against the DB (SELECT + a client-side HTTP HEAD/GET of each source_url).
- *Block on:* high — any non-zero delta or new residue after the re-run is a blocker, not a warning.
</threat_model>
