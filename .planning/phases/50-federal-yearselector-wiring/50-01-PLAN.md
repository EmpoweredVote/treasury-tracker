# Plan 50-01 — Backend: expose period_label

**Mode:** standard · **Repo:** `../EV-Accounts` (git `master`, separate Render deploy)
**Goal:** Surface the `budgets.period_label` column (added in Phase 49) through the treasury
API so the frontend can disambiguate FY1976 from the Transition Quarter and list the TQ as a
distinct period. Additive and nullable — zero behavioral change for any non-federal entity.

<threat_model>
**T-50-01 — API change breaks existing consumers / leaks bad data.**
- *Surface:* `/treasury/cities` + `/budgets` are consumed by the production frontend for every entity.
- *Threats:* (a) a SQL/shape change drops or renames an existing field; (b) period_label surfaces as `undefined` vs `null` inconsistently.
- *Mitigations:* additive column only (existing fields untouched); coalesce to `null`; integration tests assert existing city fields plus the new field; tsc typecheck.
- *Block on:* high (production API).
</threat_model>
