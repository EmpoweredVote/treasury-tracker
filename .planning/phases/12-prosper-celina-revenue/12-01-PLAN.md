    6. downloadPDF(url, dest) — async fetch + write (same pattern as processRevenuePDF.js)
    7. extractPdfText(pdfPath) — execSync pdftotext -layout, maxBuffer 256MB, split on \n, strip \x0c
    8. findRevenueSection(lines) — finds "STATEMENT OF REVENUES, EXPENDITURES AND CHANGES IN FUND BALANCE" followed by "GENERAL FUND" and "BUDGET AND ACTUAL" within 10 lines.     9. parseRevenueLines(lines, startIdx) — collects revenue rows, stops at /^EXPENDITURES\b/i. For each line: extract label (left side, first 40 chars trimmed) + money amounts (right side). Skip lines with no amounts. Skip "Total revenues" rows (used for validation only, not for line items). Handle pendingRow pattern: label-only lines set currentLabel; next line with values gets that label.
    10. buildTree(rows, fund) — builds JSON tree in treasury_sync_budget_tree RPC format. department = fund name (use "General Fund"), category = revenue line item label, fund = "Governmental Funds". Format: [{n, a, c: [{n, a, i: [{d, a, aa, f, e}]}]}]
    11. validateTotal(extracted, expected, fyLabel) — returns boolean; prints extracted, expected, % diff to console; returns true if null expected (with console.warn)
    12. processFY(supabase, muniId, fiscalYear, opts) — downloads/uses cached PDF, runs pdftotext, finds section, parses revenue, validates, loads to DB. Sets last_synced_at on data_source after successful RPC. Returns { fy, passed, total } object. Data_source lookup uses composite key: municipality_id + api_type='pdf_download' + dataset_id='fy'+fiscalYear + dataset_type='revenue'. Do NOT create a new data_source — the Phase 9 seeder already created these rows.
    13. main() — parseArgs with dry-run/verbose/no-cache/pdf/fy flags; municipality lookup for 'Prosper'; loops over [2023, 2024, 2025] (or single --fy value); calls processFY for each; per-FY failure does NOT block other FYs; prints summary table at end.
