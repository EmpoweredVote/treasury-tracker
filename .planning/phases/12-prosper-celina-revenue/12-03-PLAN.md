  <files>scripts/processCelinaRevenuePDF.js</files>
  <action>
    Create `scripts/processCelinaRevenuePDF.js` following processGarlandBudget.js structure
    strictly. This is a standalone file — do NOT import from or share code with
    processProsperjRevenuePDF.js.

    **Celina-specific differences from Prosper:**

    1. Single FY (FY2025 only) — no per-FY loop needed
    2. Sentence-case section header (not ALL CAPS):
       Section anchor: "Statement of Revenues, Expenditures and Changes in Fund Balances"
       followed by "Budget and Actual - General Fund" within 10 lines
    3. Expected total: $129,568,278 (Total Governmental Revenues from FY2025 ACFR, verified)
    4. Data_source: id=0e2e54c5 — use composite key lookup, not hardcoded ID
    5. PDF URL: https://www.celina-tx.gov/DocumentCenter/View/15082/City-of-Celina-Texas---FINAL-ACFR-FY2025
    6. Cache path: C:/tmp/celina_acfr_fy2025.pdf

    **File structure:**
    1. Shebang + JSDoc comment (usage examples)
    2. Imports: execSync, createClient, parseArgs, fs, path, fileURLToPath
    3. Constants: SUPABASE_URL, SUPABASE_KEY, PDF_URL, CACHE_PATH, FISCAL_YEAR = 2025,
       EXPECTED_TOTAL = 129_568_278, TOLERANCE = 0.20
    4. parseMoney() — identical to processGarlandBudget.js
    5. extractPdfText(pdfPath) — execSync pdftotext -layout, maxBuffer 256MB, split on \n, strip \x0c
    6. findRevenueSection(lines) — finds "Statement of Revenues, Expenditures and Changes in Fund Balances"
       (sentence case, exact match) followed by "Budget and Actual - General Fund" within 10 lines.
       Returns the line index of the section start, or -1 if not found.
    7. parseRevenueLines(lines, startIdx) — collect revenue rows, stop at /^Expenditures\b/i.
       Handle pendingRow pattern (label-only lines set currentLabel; next values line claims it).
       Skip "Total revenues" label lines (use hardcoded expected total for validation, not this).
       Skip label-only lines with no dollar amounts (log warning, do not substitute $0).
    8. buildTree(rows) — same JSON format as processRevenuePDF.js buildTree(). department = "General Fund",
       fund = "Governmental Funds", for each revenue row: category = label, a = adopted_amount,
       aa = actual_amount (null if not available). Format: [{n, a, c: [{n, a, i: [{d, a, aa, f, e}]}]}]
    9. validateTotal(extracted, expected) — prints comparison, returns boolean
    10. main() — parseArgs (dry-run/verbose/no-cache/pdf flags); Celina municipality lookup;
        download if needed; pdftotext; find section; parse revenue; validate; on pass: data_source
        composite key lookup, update base_url, delete prior rows, call treasury_sync_budget_tree RPC
        (p_dataset_type: 'revenue'), set last_synced_at; print result summary.

    **Data_source lookup (Celina FY2025 revenue — row id=0e2e54c5):**
    ```javascript
    const { data: ds } = await supabase.schema('treasury').from('data_sources')
      .select('id, last_synced_at')
      .eq('municipality_id', muniId)
      .eq('api_type', 'pdf_download')
      .eq('dataset_id', 'fy2025')
      .eq('dataset_type', 'revenue')
      .maybeSingle();
    ```
    If not found: log error and exit(2). Do NOT create a new row.

    **CLI flags:**
    - --dry-run: parse and print, skip all DB writes
    - --verbose: log parse decisions to stderr
    - --no-cache: re-download even if cache exists
    - --pdf <path>: override the cache path with a local file

    **Section detection note:** Celina's all-funds governmental table also splits across two
    pdftotext page-blocks. Avoid parsing it. Target only the "Budget and Actual - General Fund"
    statement, which has labels and values on the same lines. If other governmental funds
    (Debt Service, Street Construction, etc.) are needed for a complete total, note them as a
    TODO in comments but do not implement for v1.3 — the validation check against $129,568,278
    will likely fail if only General Fund is extracted; in that case log the failure clearly.
    If the General Fund Budget-and-Actual section alone does not produce a total within 20% of
    $129,568,278, also attempt parsing the wide all-funds table or individual fund schedules.
    The goal is a passing validation — use whatever parsing approach achieves it for v1.3.
