<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public state ACFR site → local disk | untrusted PDF/HTML fetched over the network into a local working dir |

This is a documentation-only, read-only recon plan: it fetches public ACFR PDFs, runs `pdftotext`, and writes local markdown. No DB, no secrets, no user input, no network writes. The honest threat surface is minimal.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-01 | Spoofing/Tampering | fetched "ACFR" PDF that is actually a soft-404 HTML page (HTTP 200 + HTML body) mistaken for a real document | mitigate | Filter every download by Content-Type `application/pdf` or size (>~1MB), never by HTTP status alone (CA-SCO soft-404 caution, 98-RECON). Confirm the exact statement title + "General Fund" column header + units before trusting any extracted figure. |
| T-112-02 | Tampering | extracting the wrong statement (government-wide Statement of Activities, or a budgetary/forecast schedule) instead of the Governmental Funds GENERAL FUND column | mitigate | Confirm the statement title is "Statement of Revenues, Expenditures and Changes in Fund Balances — Governmental Funds" and the column header is the General Fund column; tie the extracted GF Total revenues to the printed page total before recording (D-05/D-08.3). |
| T-112-03 | Tampering | recording a non-durable (Wayback/one-off) URL that will rot, breaking the always-sourced standard | mitigate | Reject non-durable-only years to the gap log (D-06); only a stable re-fetchable per-year URL pattern is recorded as loadable. |

No package installs in this plan (poppler `pdftotext` is a pre-existing system tool) → no supply-chain checkpoint needed. Some state sites need a browser User-Agent (tn.gov precedent) — a UA header on a public GET is normal client behavior, not evasion.
</threat_model>
