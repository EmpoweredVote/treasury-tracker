# Plan 132-01 — Seed 4 Pima municipalities + link to existing Pima County node

**Mode:** standard
**Goal:** Give each municipality a home under the existing Pima County node before any budget loads. One idempotent seeder upserts the four city entities and links each to Pima via `municipalities.county_id`. After this, `US → Arizona → Pima County → {Oro Valley|Marana|Sahuarita|South Tucson}` resolves and the Cities-in-County panel lists all five (with Tucson).

No budget load, no enrichment, no schema change, no `data_source` rows (those are 132-02). **The Pima County node already exists (v2.17) — reuse it, never create a second.**

<threat_model>
**T-132-01 — Privileged writes to the shared production `municipalities` table.**
- *Surface:* service-role upsert/insert into `treasury.municipalities` for four cities + a `county_id` link.
- *Threats:* (a) non-idempotent insert duplicating a city on re-run; (b) creating a SECOND Pima County node instead of reusing the v2.17 one; (c) repointing a city already linked elsewhere; (d) fabricated population; (e) clobbering Tucson's existing Pima link.
- *Mitigations:* select-by-(name,state,entity_type) → update-or-insert (never blind insert); resolve the Pima node by its known id / (name='Pima County',state='AZ',entity_type='county') and REUSE it — never create; set `county_id` only when NULL or already Pima; pin 2024 Census populations; read Tucson's row read-only (do not touch).
- *Block on:* high (duplicate node or mis-link corrupts shared production navigation).
</threat_model>
