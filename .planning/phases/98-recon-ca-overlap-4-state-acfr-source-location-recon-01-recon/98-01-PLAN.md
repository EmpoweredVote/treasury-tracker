# Plan 98-01 — CA node reconnaissance + recommended upgrade target

**Mode:** standard
**Goal:** Resolve California's GF-node situation against the pre-existing v1.7 CA-state-budget entity from live evidence, check MA v1.8 for the same overlap pattern, and produce a single decision-ready recommended upgrade target with concrete reconcile/retire steps. Documentation only — no loads, no mutations. Satisfies RECON-01.

<threat_model>
**T-98-01 — A wrong CA inventory sends Phase 99 at the wrong node, creating a duplicate/conflicting California node.**
- *Surface:* read-only probes of `treasury.budgets` / municipalities / data_sources for CA + MA; a recommendation doc.
- *Threats:* (a) probing the wrong entity key and concluding "no overlap" when one exists; (b) assuming basis/source from labels instead of reading rows; (c) recommending upgrade-in-place when v1.7 data is structurally different and would be silently dropped.
- *Mitigations:* enumerate ALL CA rows by entity id, not by guessed name; read actual `data_source` + basis fields, don't infer; the recommendation must list what data each node holds and what happens to it under the recommended path; decision stays Chris's (recon recommends only).
- *Block on:* high.
</threat_model>
