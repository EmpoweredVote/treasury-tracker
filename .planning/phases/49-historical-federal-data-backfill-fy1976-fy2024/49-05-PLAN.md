# Plan 49-05 — Full backfill run + audit + coverage verification

**Mode:** standard
**Goal:** Actually land the data. Orchestrate the three loaders across FY1976–FY2024 and the
TQ, then prove gap-free coverage, full sourcing, and per-year disclosures. This is the plan
where app-visible rows are written, so it carries the execution checkpoint.

<threat_model>
**T-49-03 — Bulk write corrupts existing data or produces silent gaps.**
- *Surface:* ~150 budget rows (49 years × 3 lenses + 3 TQ) written to a production app table.
- *Threats:* (a) a mid-run failure leaves partial coverage; (b) FY2025 rows accidentally overwritten; (c) a year silently skipped (gap) without erroring; (d) duplicate rows from a re-run.
- *Mitigations:* loaders are idempotent (data_source-scoped pre-delete + RPC upsert); the orchestrator iterates an explicit year list and records per-(year,lens) success/tier so skips surface; FY2025 data_sources use `dataset_id='fy2025'` and are never targeted (loop is 1976–2024 + tq1976); a coverage SQL gate runs after the load and fails on any missing pair; resumable (re-run skips/overwrites cleanly).
- *Block on:* high.
</threat_model>

## Tasks

<task id="49-05-01" type="execute">
<action>
Create `scripts/backfillFederalHistory.mjs` — a thin orchestrator that loops the explicit year list FY1976..FY2024 and invokes each loader (`loadFederalFunctions.js --fy N`, `loadFederalAgencies.js --source omb --fy N`, `loadFederalReceipts.js --fy N`) via execFileSync, then runs each loader once with `--tq`. Support `--dry-run` (pass through to children) and `--only <function|agency|receipts>`. Collect per-(year,lens) result: tier selected, reconciliation delta, rows written. Print a final matrix and a list of any Tier-2 (load-anyway) years. Continue on a single-year failure but exit non-zero if any (year,lens) ends with no row written.
</action>
