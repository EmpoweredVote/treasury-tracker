<objective>
Seed Sacramento's data layer and load its full operating + revenue budget history (FY2013–FY2026) into the database.

This plan creates `scripts/seedSacramentoCA.js` (a new, idempotent seeder per D-02) that UPDATES the population on the existing Sacramento municipality row, creates the two `data_sources` rows and the one `source_registry` row that `loadSacramentoCSV.js` expects, then runs the already-written loader (dry-run, then live) for both dataset types across the full year range.

Purpose: Without the seeder, `loadSacramentoCSV.js` exits immediately — it fails fast when the named data_source rows are absent (see `getDataSources()` in the loader). This plan unblocks the data load that makes Sacramento visible in the app.

Output: `scripts/seedSacramentoCA.js`; Sacramento municipality population set to 536000/2024; two data_sources rows; one source_registry row; operating + revenue budget rows for FY2013–FY2026 in `treasury.budgets` + `treasury.budget_categories`.
</objective>

<key_facts>
- Sacramento municipality already exists. UUID = `9722596e-1102-4aca-8758-c32fc0c1731d` (confirmed in scripts/seedLACountyLinks.js OTHER_COUNTY_CITIES.SACRAMENTO). It has `county_id` set by Phase 25 — DO NOT touch county_id.
- The loader's `getDataSources()` looks up data_source rows by EXACT name via the `treasury_list_source_ids` RPC and `process.exit(1)`s if either is missing. Required names (exact): "Sacramento Operating Budget", "Sacramento Revenue Budget".
- The loader reads `ds.municipality_id` from the data_source row (used in the source_registry backfill UPDATE). Each data_source row MUST set `municipality_id` to the Sacramento UUID.
- The loader looks up `source_registry` by `name = 'open-budget-sacramento'` and, if found, backfills `budgets.data_source_id` with that registry id for UI attribution. If absent, the loader still loads data but skips attribution (sourceRegistryId stays null).
- `source_registry` is in the `treasury` schema and reachable via `supabase.schema('treasury').from('source_registry')`, but it was noted in Phase 24 as not exposed via the default PostgREST schema. The MCP (mcp__supabase-local) is the project-preferred tool for DB introspection and DDL.
- Loader CSV source: Open Budget Sacramento GitHub (https://openbudgetsac.org), MIT license. Full FY range FY2013–FY2026 (D-01). Loader flags: `--list`, `--dry-run`, `--operating`, `--revenue`, `--fy <year>` (repeatable).
</key_facts>
