# Plan 59-03 — basis-change notes for the newly mixed-basis cities

**Mode:** standard
**Goal:** For each city that Plan 59-01 left with a mixed-basis series (SCO all-funds history beneath GF/custom recent years), add a sourced basis-change note to the shipped `src/data/cityBasisNotes.ts` map (D-02), reusing the Phase 58 mechanism. This is data-only — the render site is already generic.

**Why no UI change (verified):** `src/App.tsx:932-945` looks up `cityBasisNotes[\`${selectedEntity.name}|${selectedEntity.state}\`]` and renders `<ComparabilityNote>` whenever the lookup returns an entry; an absent key renders nothing. So adding map entries is sufficient — the additive pattern means pure-SCO cities, the rich custom-only cities, counties, and federal pages are unaffected by construction. See `59-RESEARCH.md` §D-02.

**Which cities get a note:** the candidate set is the 7 layered cities (San Francisco, Oakland, Fresno, Riverside, Bakersfield, San Diego, Berkeley). The **authoritative final set is the mixed-basis list Plan 59-01 task 04 recorded** — a layered city whose custom recent years were fully subsumed by SCO (no surviving custom-basis rows on a different basis) does NOT mix bases and gets NO note. Author an entry only for cities that genuinely retain custom GF/transaction recent years above the SCO all-funds floor.

**Template:** the existing `Long Beach|CA` / `West Hollywood|CA` entries are the exact pattern. Each new entry states that FY2003–2024 figures come from the SCO ByTheNumbers all-governmental-funds dataset (General Fund + enterprise + debt service + all other funds) while the recent years come from the city's published General-Fund budget (or transaction data, per the city), so cross-seam comparison reflects the basis change, not a real spending change. Cite `source_name: 'CA State Controller — ByTheNumbers Expenditures'`, `source_url: 'https://bythenumbers.sco.ca.gov/d/ju3w-4gxp'`, `source_date: '2026-06-16'`.

<threat_model>
**T-59-03 — A basis note ships without a source, mislabels a city's recent-year basis, or a note is added for a city that is not actually mixed-basis (false disclosure).**
- *Surface:* `cityBasisNotes.ts` is hand-authored text rendered with a SourceChip; an unsourced or inaccurate note violates the always-sourced ground rule and can mislead.
- *Threats:* (1) an entry with no source_url/source_date; (2) a note describing the recent-year basis wrongly (e.g. calling a transaction-data city a GF city); (3) a note added for a pure-SCO or custom-only city that does not mix bases.
- *Mitigations:* (1) every entry copies the ComparabilitySource shape with source_name + durable /d/ source_url + source_date — typecheck enforces the shape; (2) the recent-year basis description is taken from each city's actual custom data_source recorded in 59-01 task 01 baseline (GF budget vs Demand-Register-style transaction data); (3) the entry set is gated on 59-01 task 04's recorded mixed-basis list — no entry for a city not on it.
- *Block on:* high (always-sourced is a project ground rule). Do not author an entry whose source_url/source_date is missing or whose recent-year basis is not grounded in the 59-01 baseline.
</threat_model>
