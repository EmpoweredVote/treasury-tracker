## Script shape

| Option | Description | Selected |
|--------|-------------|----------|
| `--rollup` mode on existing loader | Add a `--rollup` path inside `loadUtahTransparency.js`; reuse all internals directly, no new exports | ✓ |
| New sibling script (`loadUtahRollup.js`) | Dedicated bulk script importing the loader's exports, mirroring `bulkLoadStateController.js`; needs `importEntityData` etc. exported; drift risk | |
| Refactor shared core | Extract `loadUtahCore.js` both import; most "correct" long-term, most churn now | |

**User's choice:** `--rollup` mode on the existing loader.
**Notes:** Reuse `buildTree`, `buildSalaryTree`, `importEntityData`, never-overwrite guard, `toDisplayName`, `runGuardedQuery`. New code = one fetch fn + a group-by-`(entity,fy,type)` loop. Least churn; remediation, not new architecture.

## Query strategy

| Option | Description | Selected |
|--------|-------------|----------|
| One unified scan | Single GROUP BY over all 15 entities × FYs × EX/RV/PY (~1 scan, ~$0.29); drop `fund1` in memory for PY; no PII column projected | ✓ |
| Split EX/RV + separate PY scan | PY scan literally free of `fund1` + separate EX/RV scan; ~2 scans (~$0.55); "purer" but 2× cost, no functional gain since `fund1` isn't PII | |

**User's choice:** One unified scan.
**Notes:** Names-free preserved — `fund1`/`org1`/`cat1` aren't PII; PY collapses `fund1` before `buildSalaryTree` so the stored salary tree stays 2-level Department→Wages/Benefits.

## Scan safety / UX

| Option | Description | Selected |
|--------|-------------|----------|
| Dry-run preview + `--confirm` + built-in cap | Free dry-run prints est. GiB/$/quota-fit, then `--confirm` runs the real scan+write; rollup path uses a built-in ~64 GiB cap; per-entity path stays 2 GiB | ✓ |
| Require `LOADER_MAX_GIB` override each run | No preview; set the env var to run; simpler but no cost visibility | |
| Always dry-run then prompt, no built-in cap | Preview every time but rely on env override for the cap | |

**User's choice:** Dry-run preview + `--confirm` + built-in 64 GiB cap.
**Notes:** You see estimated cost before spending; default (no `--confirm`) is preview only — zero scan-billing, zero writes.

---

## Refresh semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Refresh own rows, never delete, never touch other sources | Idempotent upsert of our Transparent Utah rows; guard skips different-source rows; absent `(entity,fy,type)` left in place + logged | ✓ |
| Refresh own rows + prune vanished ones | Same, but delete our rows no longer in source; risks deleting good data on a partial scan / name shift | |
| Skip existing, only insert new | Never overwrite anything; a refresh would never update changed figures — defeats the ETL | |

**User's choice:** Refresh own rows, never delete, never touch other sources.
**Notes:** Idempotent upsert via the RPC; absent combos preserved (never silently drop loaded data).
