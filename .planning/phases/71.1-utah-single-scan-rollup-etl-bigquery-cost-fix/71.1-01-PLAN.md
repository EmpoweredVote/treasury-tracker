THE SINGLE ROLLUP QUERY (one scan; parameterized; names-free; all-funds for the GROUP BY):
  SELECT entity_name, fiscal_year, type,
         COALESCE(fund1,'Unknown') AS fund1, COALESCE(org1,'General') AS org1,
         COALESCE(cat1,'General') AS cat1, SUM(amount) AS amount
  FROM `ut-sao-transparency-prod.transaction.transaction`
  WHERE entity_name IN UNNEST(@entities)
    AND fiscal_year BETWEEN 2014 AND 2025
    AND type IN ('EX','RV','PY')
  GROUP BY entity_name, fiscal_year, type, fund1, org1, cat1

  REFINEMENT OF D-71.1-02 (document this): CONTEXT said "no WHERE filter". This query DOES add a
  WHERE (entity_name IN the 15 mapped names + FY range + the 3 types). This is COST-NEUTRAL — the
  table is unpartitioned, so the WHERE does not prune bytes scanned (~47 GiB either way) — and it is
  still ONE scan. It does NOT reintroduce per-entity querying; it just returns only our entities'
  aggregated rows instead of every Utah entity (hundreds), keeping the in-memory set small and
  avoiding importing entities with no municipality row. Never project a PII column. Never use LIKE.

THE 15 EXACT entity_names (docs/utah-entity-mapping.md — match EXACTLY, never LIKE; decoys exist):
  Cities (govt_lvl='City'): Layton City, Lehi City, Ogden City, Orem City, Provo City,
    Salt Lake City, Sandy City, St. George City, West Jordan City, West Valley City
  Counties (govt_lvl='County'): Salt Lake County, Utah County, Davis County, Weber County, Washington County
  Store under toDisplayName (drops "City" except Salt Lake City / West Valley City); counties pass through.
  Note: SLC PY ≈ 2.6M raw rows — the server-side SUM/GROUP BY returns a small aggregate; still ONE scan.

GROUPING (groupRollupRows(rows) → array of { entityName, fiscalYear, type, datasetType, tree, total }):
  key = `${entity_name}|${fiscal_year}|${type}`.
  PY  → drop fund1, re-sum by (org1,cat1), then buildSalaryTree(rows) → 2-level {n,a,c:[{n,a}]} (D-71-02).
  EX/RV → buildTree(rows, TREE_OPTS) → 3-level fund1→org1→cat1 (D-69-01).

WRITE (unchanged — reuse importEntityData per group):
  treasury_ensure_municipality(...) → treasury_sync_city_budget(p_dataset_type, p_total, p_tree,
    p_source_url, p_source_date, p_data_source_name='Transparent Utah'); findConflictingBudget skips
    a DIFFERENT-source row only. Entity-type (city|county) per the mapping for ensure_municipality.

DRY-RUN COST PREVIEW (free; exempt from QueryUsagePerDay):
  const [job] = await bq.createQueryJob({ query, params, dryRun: true });
  bytes = Number(job.metadata.statistics.totalBytesProcessed);
  print GiB = bytes/2**30, est $ = bytes/2**40 * 6.25, quota-fit = bytes <= 2**40 (1 TiB/day).
