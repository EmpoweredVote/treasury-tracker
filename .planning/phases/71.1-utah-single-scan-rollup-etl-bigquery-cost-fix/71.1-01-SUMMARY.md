# Phase 71.1: Utah Single-Scan Rollup ETL (BigQuery Cost Fix) Summary

**Names-free, cost-gated `--rollup` mode replaces the per-`(entity,FY,type)` live-query pattern that ran up ~21 TiB / ~$132 on 2026-06-19: one ~47 GiB GROUP BY scan loads all 15 Utah entities × FY2014–2025 × EX/RV/PY into Supabase for ~$0.29, idempotently.**

## Performance

- **Tasks:** 3 (Task 1 code+tests+runbook; Task 2 live free dry-run; Task 3 live --confirm refresh)
- **Files modified:** 3
- **Completed:** 2026-06-20

## Accomplishments
- Added `ROLLUP_QUERY` (single parameterized GROUP BY: entity_name, fiscal_year, type, fund1, org1, cat1, SUM(amount)) — names-free, `IN UNNEST(@entities)`, `BETWEEN 2014 AND 2025`, `type IN ('EX','RV','PY')`, never `LIKE`.
- Added `groupRollupRows(rows)`: groups by `(entity,fy,type)`; PY drops fund1 + re-sums by (org1,cat1) → `buildSalaryTree` (2-level); EX/RV → `buildTree` (3-level). FY2026 + non-mapped entities excluded.
- Added dry-run cost preview (free, bills 0 bytes, quota-exempt) printing GiB / est $ / 1 TiB-day quota-fit, plus `--confirm` gate and a built-in ~64 GiB rollup cap (per-entity path unchanged at 2 GiB).
- 30 new tests (PII-exclusion guard + groupRollupRows shape/grouping/PY-collapse/FY2026-exclusion) — **78/78 pass, 0 failing**; existing 48 stay green.
- `docs/utah-bigquery-access.md` gained the manual rollup-refresh runbook + cost-incident note.
