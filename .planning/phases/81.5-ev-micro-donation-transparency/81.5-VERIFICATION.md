### Privacy Guarantee

The DB query result is authoritative:

```
_evMicro keys: [ 'recurring_supporters', 'typical_monthly', 'as_of_fy' ]
buckets present: false
recurring_supporters: 9
typical_monthly: 10
as_of_fy: 2026
```

**No PII keys present. No bucket distribution persisted.** The three keys are: a count (not names), a median (not individual amounts), and a fiscal year. The contact IDs and email addresses used as dedup keys in `giveButterRecurringDonors` and the member user IDs used in `patreonDistinctPatrons` never leave those in-memory Maps — they are not returned in the aggregate object and are not persisted anywhere.

### WR-05 Deferral Assessment

WR-05 (GiveButter `asOf` horizon computed over all FYs, can over-suppress webhook delta) was intentionally not fixed. Assessment:

- It is pre-existing Phase 74 logic, not introduced by Phase 81.5.
- The risk window is narrow: only a re-export pulled early in the next calendar year (CY2027) would trigger it, at which point the exporter would see unexpected delta suppression on inspection.
- The micro-donation *aggregates* (the Phase 81.5 deliverable) are unaffected — `computeRecurringAggregates` uses `gbRows` independently of the `asOf` horizon.
- The only affected thing is the webhook dedup, which is a revenue accuracy concern for Phase 74-era logic.

**Verdict: acceptable deferral.** This is not a gap for Phase 81.5.
