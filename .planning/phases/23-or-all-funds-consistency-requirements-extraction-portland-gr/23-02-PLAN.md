Page detection signal: a page is a data page when `'Total City Budget' in text and 'Resources and Requirements' in text and 'Personnel Services' in text`. The `'Personnel Services'` guard eliminates the Table-of-Contents false positive (Pitfall — TOC also contains the first two strings).

Implement multi-page continuation for FY2026 (spans pages 116–117). Track a `found_data_page` flag. A continuation page satisfies `found_data_page and 'Total City Budget' in text and 'Resources and Requirements' in text and 'Personnel Services' not in text`. If a page is neither a data page nor a continuation: `break` if `found_data_page` is already True (past the table), else `continue`. Accumulate rows across the data page and any continuation page.

Detect fiscal year via the existing `detect_fiscal_year(text)` helper, set once when first found.

For each row in `tables[0]`: skip if `not row or not row[0]`. Normalize `name = row[0].replace('\n', ' ').strip()` then take `name = name.split('\n')[0].strip()` to handle FY2026 compound cell keys like `'Requirements\nBureau Expenditures'`. Skip if `name` is empty or in the skip set. Define `PORTLAND_REQUIREMENTS_SKIP = {'Resources', 'Requirements', 'External Revenues', 'Internal Revenues', 'Bureau Expenditures', 'Fund Expenditures', 'Total External Revenues', 'Total Internal Revenues', 'Total Resources', 'Less Intracity Transfers', 'Total NET Budget', 'Total Bureau Expenditures', 'Total Fund Expenditures', 'Total Requirements', 'Ending Fund Balance', 'Beginning Fund Balance'}`. Guard `if len(row) < 6 or row[5] is None: continue` (Adopted is index [5]; the `len(row) >= 6` guard protects against column-shift per Pitfall 5). Parse `adopted = parse_money(row[5])`, skip if `<= 0`.

Append the same dict shape as the other extractors: `{ 'category', 'adopted_amount', 'fiscal_year', 'page_num' }`. The category rows that survive the skip set are the expenditure line items (Personnel Services, External/Internal Materials and Services, Capital Outlay, Debt Service, Contingency, Fund Transfers - Expense, Debt Service Reserves) plus Ending Fund Balance is intentionally skipped so the summed total stored equals gross Total Requirements minus Ending Fund Balance — NOTE: see Decision below.

Decision (locked by planner for consistency with Gresham/Troutdale): store the GROSS Total Requirements figure. The simplest robust approach: collect the line-item rows above and let the loader sum them; the planner's intent is that the loader-summed total approximates the published Total Requirements. If the summed line items do not reconcile to within 1% of the published "Total Requirements" value for FY2026, the executor MUST instead capture the `'Total Requirements'` row's Adopted value directly as a single category named `'Total Requirements'` (remove it from the skip set in that fallback path) so the stored total exactly equals the published gross figure. Verify reconciliation in the dry-run before live load.

Extend `__main__` argparse: add `'requirements'` to `--mode` choices and dispatch `args.mode == 'requirements'` to `extract_requirements(args.pdf_path)`.
