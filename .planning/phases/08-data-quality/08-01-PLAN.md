  <name>Task 1: Fix max_tokens truncation in bulkLoadPDF.js</name>
  <files>scripts/bulkLoadPDF.js</files>
  <action>
In `scripts/bulkLoadPDF.js`, modify `callHaikuWithRetry` (currently around lines 260-304):

1. Change `max_tokens: 2048` to `max_tokens: 8192` in the `anthropic.messages.create` call. Haiku 4.5 supports 64k output tokens; 8192 handles the worst realistic dense ACFR page (~40 line items × ~200 tokens each) without unnecessary cost. Do NOT raise to 64k — that would balloon per-page cost without benefit.

2. Immediately after `await anthropic.messages.create(...)`, BEFORE reading `response.content[0].text`, add a guard:

```javascript
if (response.stop_reason === 'max_tokens') {
  return {
    page_type: 'other',
    confidence: 0,
    reason: 'max_tokens_truncation: response truncated, JSON incomplete',
    rows: [],
  };
}
```

This must return immediately — do NOT throw, do NOT call `extractJSON`, do NOT retry. The retry loop is for transient API/network errors; truncation is deterministic — retrying produces the same truncated output. Returning a well-formed confidence=0 object lets the existing flagged-pages logic record the page in the review log without crashing.

3. Place the guard inside the existing `try { ... } catch` block, after the `messages.create` call but before `const text = response.content?.[0]?.text;`. This way the guard short-circuits the function before any parse attempt.

Do not change the retry/backoff logic, the validator, or any other part of the function.

**Change A — Update EXTRACTION_PROMPT (around lines 185-209):**

Update the budget_table example to include `"section_heading": "Public Safety"`, and update the narrative example to include `"section_heading": null`. Add an explanatory rule:

```
- section_heading: if a major ACFR section header is visible on this page (e.g. "Public Safety", "Public Works", "General Government", "Culture and Recreation"), return the heading text; otherwise return null. This is used to attribute department for budget rows on subsequent pages that lack an explicit department column.
```

Also add a paragraph near the top of the rules block explaining the optional context line that may be appended to the prompt at runtime: "If a 'Context: Current ACFR section is "<name>".' line is present below, use that as the department for any row that does not have its own department/header label."

**Change B — Build the per-page prompt with optional context:**

Convert the module-level `EXTRACTION_PROMPT` constant into `EXTRACTION_PROMPT_BASE` (rename), then add a small helper at module level:

```javascript
function buildExtractionPrompt(sectionContext) {
  if (!sectionContext) return EXTRACTION_PROMPT_BASE;
  return EXTRACTION_PROMPT_BASE + '\n\nContext: Current ACFR section is "' + sectionContext + '". Apply as department for rows without an explicit department header.';
}
```

**Change C — Update validateExtractionResult:**

After the existing `rows` array check, add:

```javascript
if ('section_heading' in obj && obj.section_heading !== null && (typeof obj.section_heading !== 'string' || obj.section_heading.trim() === '')) {
  return { ok: false, reason: 'Schema violation: section_heading must be null or non-empty string' };
}
```

If the field is missing entirely, treat that as null (do NOT reject — older Haiku responses may not include the field, but new prompts will).

**Change D — Update callHaikuWithRetry signature and processPDF loop:**

1. Add a third parameter to `callHaikuWithRetry`: `callHaikuWithRetry(base64, pageNum, prompt, opts)` — pass the prompt text in instead of using the module-level constant. Replace the existing `text: EXTRACTION_PROMPT` inside the messages payload with `text: prompt`.

2. In `processPDF` (around line 320), declare `let currentSection = null;` INSIDE the function (NOT at module level — research §Pitfall 2: state must reset per call to prevent bleed across documents).

3. In the per-page loop (around line 346), build the prompt per-page and pass it in:

```javascript
const prompt = buildExtractionPrompt(currentSection);
const result = await callHaikuWithRetry(base64, pageNum, prompt, opts);
```

4. After receiving the result, BEFORE the `result.page_type !== 'budget_table'` check, update the section state:

```javascript
if (result && result.section_heading) {
  currentSection = result.section_heading;
}
```

This way every page (including narrative/cover/notes pages) can update the running section heading.

5. In the row-collection block (around lines 376-378), apply the fallback before pushing to `budgetRows`:

```javascript
for (const row of result.rows) {
  if (!row.department && currentSection) {
    row.department = currentSection;
  }

}
```

Do not change the truncate-and-reload step, the RPC call, or any unrelated logic.
