**Step 1 — BEFORE audit (capture baseline):**

Run the following query against Supabase via the service-role key. Use a Node one-liner or psql; either works. The goal is a snapshot of % Unknown rows for the three cities before re-extraction:

```sql
SELECT
  m.name AS city,
  b.fiscal_year,
  COUNT(*) FILTER (WHERE bdi.name = 'Unknown') AS unknown_rows,
  COUNT(*) AS total_rows,
  ROUND(100.0 * COUNT(*) FILTER (WHERE bdi.name = 'Unknown') / NULLIF(COUNT(*), 0), 1) AS pct_unknown
FROM treasury.budget_items bdi
JOIN treasury.budgets b ON bdi.budget_id = b.id
JOIN treasury.municipalities m ON b.municipality_id = m.id
WHERE m.name IN ('Allen', 'Prosper', 'Celina')
  AND b.dataset_type = 'operating'
GROUP BY m.name, b.fiscal_year
ORDER BY m.name, b.fiscal_year;
```

Save the result table as a markdown block under "BEFORE state" — include city, fiscal_year, unknown_rows, total_rows, pct_unknown.

If the audit query schema/RPC name differs from research notes, the table names are `treasury.budget_items` (joined via `budget_id` to `treasury.budgets`, joined via `municipality_id` to `treasury.municipalities`). The "Unknown" department text lands in `budget_items.name` because of the `cat = row.department || 'Unknown'` fallback in `processPDF` (bulkLoadPDF.js around line 396) — that's the column to filter on. If `bdi.name` is wrong, inspect the schema and adjust before running.
