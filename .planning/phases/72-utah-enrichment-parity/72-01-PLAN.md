  CLI: node scripts/loadUtahEnrichment72.mjs            # dry-run: derive worklist + print mapping, NO writes
       node scripts/loadUtahEnrichment72.mjs --apply    # upsert universal rows into treasury.category_enrichment

    UT_IDS   = municipalities where state='UT' AND entity_type IN ('city','county')  (exclude the state row)
    For dataset_type in (operating, revenue): collect depth-0 link_keys (FUND worklist) AND depth-1
      link_keys (COMPOSITE worklist), each with its set of distinct municipality_ids.
    For dataset_type = salaries: collect depth-0 link_keys (DEPT worklist) with distinct muni set.
    existingUniversal = all category_enrichment.name_key where municipality_id IS NULL (so CA universals
      like police/fire/finance are treated as already-covered and inherited, not re-authored).
  Resolver (per key, returns { row, via }):
    FUND key (op/rev depth-0):  UTAH_FUND_ROUTES first-match → UTAH_FUND_CONCEPTS; else general_fund (via:'fallback:general_fund', WRITTEN).
    COMPOSITE key (op/rev depth-1): dept = part after the LAST '|'; route dept through
      UTAH_DEPT_EXTRA_ROUTES → exact CONCEPTS id → Phase61 ROUTE_RULES → general_dept. ALWAYS WRITE
      (general_dept fallback at depth-1 reads sensibly under a fund — D-72-09). plain_name from the concept.
    DEPT key (salaries depth-0): route dept through UTAH_DEPT_EXTRA_ROUTES → exact CONCEPTS → ROUTE_RULES.
      If the ONLY match is the general_dept fallback → DEFER (do not write); increment deferredSingleCity-style
      counter. If it routes to a real concept (even single-city) → WRITE.
  Row shape (identical to SoCal): { name_key, municipality_id:null, plain_name, short_description,
    description, tags, source:'ai', confidence, evidence_summary (Phase-72 generic note), generated_at }.
  Upsert: supabase.from('category_enrichment').upsert(batch,{ onConflict:'name_key,municipality_id' }) in
    batches of ~200. $-leak guard BEFORE write: abort if any /\$\s?\d/ in description+plain_name+short_description.
  Logging (dry-run + apply): existing-universal count, worklist sizes per bucket, resolution via-counts,
    fund-fallback list, depth-1 general_dept-fallback count, salaries DEFERRED single-city count, $-leak count (must be 0).
  Supabase client: createClient(URL, SERVICE_ROLE_KEY||SERVICE_KEY, { db:{ schema:'treasury' } }); load .env.local/.env.
  GENERATED_AT: env override (e.g. PHASE72_TS) else a fixed ISO literal '2026-06-20T00:00:00.000Z'.
