Step B — DB verification via `mcp__supabase-local__execute_sql` (per project memory: prefer Supabase MCP over manual Dashboard checks).

Query 1 — Confirm 2 budget rows exist for LA with correct shape:
```sql
SELECT
  b.fiscal_year,
  b.dataset_type,
  b.total_amount,
  b.row_count,
  m.name AS city,
  m.state
FROM treasury.budgets b
JOIN treasury.municipalities m ON m.id = b.municipality_id
WHERE m.name = 'Los Angeles' AND m.state = 'CA'
ORDER BY b.fiscal_year, b.dataset_type;
```
Expected: exactly 2 rows, both `dataset_type='operating'`, fiscal_year IN (2025, 2026), `total_amount > 0` (FY2025 should be in the ~$19.8B range per RESEARCH.md), `row_count` matching the dry-run row counts within tolerance.

Query 2 — Confirm category tree exists for each budget:
```sql
SELECT
  b.fiscal_year,
  COUNT(*) FILTER (WHERE bc.depth = 0) AS top_level_categories,
  COUNT(*) FILTER (WHERE bc.depth = 1) AS subcategories,
  COUNT(*) AS total_category_rows
FROM treasury.budgets b
JOIN treasury.budget_categories bc ON bc.budget_id = b.id
JOIN treasury.municipalities m ON m.id = b.municipality_id
WHERE m.name = 'Los Angeles' AND m.state = 'CA'
GROUP BY b.fiscal_year
ORDER BY b.fiscal_year;
```
Expected: 2 rows; each shows `top_level_categories` >= 50 (RESEARCH.md says 58–59 unique departments); `subcategories > 0`; `total_category_rows > 100`.

Query 3 — Confirm NO revenue budget rows for LA (operating only for Phase 15):
```sql
SELECT COUNT(*) AS revenue_rows
FROM treasury.budgets b
JOIN treasury.municipalities m ON m.id = b.municipality_id
WHERE m.name = 'Los Angeles' AND m.state = 'CA' AND b.dataset_type = 'revenue';
```
Expected: `revenue_rows = 0`.
