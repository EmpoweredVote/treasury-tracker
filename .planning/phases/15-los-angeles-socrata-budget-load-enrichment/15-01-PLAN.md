<objective>
Create the `scripts/seedLADataSources.js` Node.js seeder that (1) inserts a `treasury.municipalities` row for Los Angeles, CA with its 2024 Census population, and (2) seeds a single `treasury.data_sources` row for the LA Operating Budget Socrata dataset `uyzw-yi8n` on `controllerdata.lacity.org`. This is the control plane for Plan 15-02's loader — once these two rows exist, `bulkLoadBudget.js` can load LA with zero code changes.

Purpose: Establish LA as a new municipality in the DB (first CA city — all prior cities were TX) and create the single Socrata `data_sources` row that drives Plan 15-02's live load. The seeder must be idempotent so it is safe to re-run. Revenue dataset (`6cbx-e2fd`) is deliberately excluded per RESEARCH.md — only operating expenditures are loaded for Phase 15.

Output:

- 1 new row in `treasury.municipalities`: Los Angeles, CA (population 3,878,704, year 2024).
- 1 new row in `treasury.data_sources`: 'Los Angeles Operating Budget' linked to the LA municipality.

```javascript
#!/usr/bin/env node
/**
 * Los Angeles Data Sources Seeder
 *
 * Creates (or updates):
 *   1. treasury.municipalities row for Los Angeles, CA (population 3878704, year 2024)
 *   2. treasury.data_sources row for the LA Operating Budget Socrata dataset (uyzw-yi8n)
 *
 * Idempotent: safe to re-run. Looks up existing rows by name and updates them
 * in-place; inserts only when the row does not exist yet.
 *
 * Revenue dataset 6cbx-e2fd is intentionally NOT seeded — only goes through FY2022
 * and contains 35 summary rows per year (not line-item data). See 15-RESEARCH.md.
 *
 * Usage:
 *   SUPABASE_SERVICE_KEY=... node scripts/seedLADataSources.js
 *   SUPABASE_SERVICE_ROLE_KEY=... node scripts/seedLADataSources.js
 */

import { createClient } from '@supabase/supabase-js';
```

2) Config (mirror Dallas seeder env handling):
```javascript
const SUPABASE_URL = process.env.SUPABASE_URL || 'https://kxsdzaojfaibhuzmclfq.supabase.co';
const SUPABASE_KEY = process.env.SUPABASE_SERVICE_KEY || process.env.SUPABASE_SERVICE_ROLE_KEY;
if (!SUPABASE_KEY) { console.error('Missing SUPABASE_SERVICE_KEY env var'); process.exit(1); }
const supabase = createClient(SUPABASE_URL, SUPABASE_KEY);
```

3) Municipality payload constant — values straight from 15-RESEARCH.md:
```javascript
const LA_MUNICIPALITY = {
  name: 'Los Angeles',
```

4) `upsertMunicipality(m)` helper — must return the resolved id. Pattern:
   - SELECT id FROM treasury.municipalities WHERE name = m.name AND state = m.state (`.maybeSingle()`)
   - If row exists: UPDATE by id (preserve created_at), return existing id
   - If not exists: INSERT row, return new id
   - On any error: `console.error(...)` and `process.exit(1)`
   - Log whether the row was inserted or updated and print the id

5) `LA_DATA_SOURCE(municipalityId)` factory — returns the data_sources payload. The column_mapping MUST match exactly what `bulkLoadBudget.js` reads (verified in 05-02-SUMMARY.md and 15-RESEARCH.md):
```javascript
function LA_DATA_SOURCE(municipalityId) {
  return {
    name: 'Los Angeles Operating Budget',
    api_type: 'socrata',
    dataset_type: 'operating',
    base_url: 'https://controllerdata.lacity.org',   // NOT data.lacity.org (Pitfall #1)
    dataset_id: 'uyzw-yi8n',
    column_mapping: {
      fiscal_year_column: 'budget_fiscal_year',
      approved_amount_column: 'adopted_budget_amount',
      actual_amount_column: 'total_expenditures',
      category_column: 'department_name',
      subcategory_column: 'fund_name',
    },
    fiscal_years: [2025, 2026],
    municipality_id: municipalityId,
  };
}
```

6) `upsertDataSourceByName(src)` helper — copy the exact `upsertByName` function from `scripts/seedDallasDataSources.js` lines 71-112 (lookup by name, update-if-exists, insert-if-not, return the row).

7) `main()` — sequence:

   g. Print confirmation line: `Verification: treasury_list_source_ids returns 1 Los Angeles operating budget source.`

8) Fatal handler at bottom: `main().catch(err => { console.error('Fatal:', err); process.exit(1); });`

CRITICAL pitfalls to honor (from 15-RESEARCH.md):
- `base_url` MUST be `https://controllerdata.lacity.org` (NOT `https://data.lacity.org`). Pitfall #1.
- `fiscal_year_column` MUST be `'budget_fiscal_year'` — this is a STRING field in Socrata; `bulkLoadBudget.js` quotes the value when building the WHERE clause. Pitfall #2.
- Municipality row MUST be inserted BEFORE the data_sources row — `data_sources.municipality_id` is a FK. Pitfall #4. Step 7b runs before 7d for exactly this reason.
- Do NOT create a revenue data_sources row. Pitfall #3 — `6cbx-e2fd` only has data through FY2022 and is summary-level (35 rows/year).
- The schema is `treasury` — use `.schema('treasury').from(...)` exactly like the Dallas seeder.
- Use `.maybeSingle()` when checking existence (returns null instead of throwing on 0 rows).

Do NOT:
- Inline raw SQL — use the Supabase JS client like the Dallas seeder.
- Hardcode the municipality id (LA is not yet in the DB — resolve it at runtime via step 7b).
- Rename or omit any column_mapping key — `bulkLoadBudget.js` reads these exact keys (Plan 05-02 verified).
- Add population data via a separate loader — embed it directly in the seeder. (We do NOT need to extend `loadTXPopulation.js` since LA is in `sub-est2024_6.csv`, a different file, and we only need one city; hardcoding 3878704 with population_year=2024 is appropriate per RESEARCH.md.)
