Step A — Live enrichment (FY2025 — covers the depth-0 vocabulary for both fiscal years per RESEARCH.md Pitfall #5):

Must exit 0. Capture stdout (count of categories enriched, actual API cost if reported).

Step B — Optional FY2026 sweep (defensive; idempotent — skips already-enriched categories). Only run if the FY2025 enrichment did NOT cover any FY2026-specific departments. To decide, run a quick SQL check first:
```sql
-- Count distinct depth-0 categories in LA budgets per year that lack enrichment
SELECT b.fiscal_year, COUNT(DISTINCT bc.id) AS unenriched_top_level
FROM treasury.budget_categories bc
JOIN treasury.budgets b ON b.id = bc.budget_id
JOIN treasury.municipalities m ON m.id = b.municipality_id
LEFT JOIN treasury.category_enrichment ce
  ON ce.category_id = bc.id AND ce.municipality_id = m.id
WHERE m.name = 'Los Angeles' AND m.state = 'CA'
  AND bc.depth = 0
  AND ce.id IS NULL
GROUP BY b.fiscal_year
ORDER BY b.fiscal_year;
```
If `unenriched_top_level > 0` for FY2026, run:
```bash
node scripts/enrichCategories.js --city "Los Angeles" --state "CA" --year 2026
```
(Pitfall #5: enrichCategories.js defaults to `--year 2025`; FY2026-only departments require explicit `--year 2026`.)

If `unenriched_top_level = 0` for both years, skip Step B.

Step C — DB verification via `mcp__supabase-local__execute_sql`.

Query 1 — Confirm enrichment rows exist with correct scoping:
```sql
SELECT
  COUNT(*) AS total,
  COUNT(*) FILTER (WHERE ce.municipality_id IS NULL) AS null_count,
  COUNT(*) FILTER (WHERE ce.description IS NULL OR ce.description = '') AS blank_desc,
  MIN(LENGTH(ce.description)) AS min_desc_length,
  MAX(LENGTH(ce.description)) AS max_desc_length
FROM treasury.category_enrichment ce
JOIN treasury.municipalities m ON m.id = ce.municipality_id
WHERE m.name = 'Los Angeles' AND m.state = 'CA';
```
Expected: `total >= 50`, `null_count = 0`, `blank_desc = 0`, `min_desc_length > 0` (descriptions are non-empty strings).

Query 2 — Duplicate check (idempotency proof — re-run enrichment, expect 0 new rows):
```bash
node scripts/enrichCategories.js --city "Los Angeles" --state "CA"
```
Then:
```sql
SELECT category_id, COUNT(*) AS n
FROM treasury.category_enrichment ce
JOIN treasury.municipalities m ON m.id = ce.municipality_id
WHERE m.name = 'Los Angeles' AND m.state = 'CA'
GROUP BY category_id
HAVING COUNT(*) > 1;
```
Expected: 0 rows.

Query 3 — Bleed check (per project memory `project_enrichment_scoping_fix.md`):
```sql
-- LA enrichments must NOT reference TX cities by name in descriptions
SELECT bc.name AS category_name, ce.description
FROM treasury.category_enrichment ce
JOIN treasury.budget_categories bc ON bc.id = ce.category_id
JOIN treasury.municipalities m ON m.id = ce.municipality_id
WHERE m.name = 'Los Angeles' AND m.state = 'CA'
  AND (
    ce.description ILIKE '%Dallas%' OR
    ce.description ILIKE '%Plano%' OR
    ce.description ILIKE '%Frisco%' OR
    ce.description ILIKE '%McKinney%' OR
    ce.description ILIKE '%Allen%' OR
    ce.description ILIKE '%Garland%' OR
    ce.description ILIKE '%Wylie%' OR
    ce.description ILIKE '%Murphy%' OR
    ce.description ILIKE '%Princeton%' OR
    ce.description ILIKE '%Richardson%' OR
    ce.description ILIKE '%Prosper%' OR
    ce.description ILIKE '%Celina%' OR
    ce.description ILIKE '%Sachse%'
  );
```
Expected: 0 rows. (Spurious matches on "Allen" inside other words like "challenge" or generic city names embedded in legitimate context are possible — manually review any results to confirm they are not bleed.)
