<objective>
Prove the Phase 84-01 loader against the known-good target AND prove the new CASH/MOD fallback path, then pin down how much history Ohio actually publishes as XLSX — the two halves of OHSRC-02 and the de-risk gate for the whole milestone.

1. **Prove (GAAP):** a `--dry-run` on Columbus FY2024 GAAP must reproduce the recon-verified figures (Total Revenues ≈ $2.166B, Income Taxes ≈ $1.145B, Police ≈ $810M, pop 913,985) with zero writes. If it doesn't, the loader (84-01) is wrong and must be fixed before any bulk load.
2. **Prove (fallback):** a `--dry-run` on one real CASH- or MOD-basis city — pulled from the smaller non-GAAP workbook — must parse cleanly through the same tree builders with the basis tagged. This de-risks Phase 85's mixed-basis fallback (OHCITY-02) here, instead of discovering surprises mid-bulk (CONTEXT D-03).
3. **Discover + document the floor:** probe the static ohioauditor.gov SummarizedReports file URLs across YEAR 2016–2025 × basis {GAAP, CASH, MOD}, record every workbook that resolves as a committed `scripts/ohioAosDatasets.json` manifest (FY×basis → URL), and document the earliest available XLSX year as the history floor.

Output: the committed FY×basis→URL manifest + the loader reading per-(FY,basis) source_url from it. No bulk load (that is Phase 85).
</objective>

<!-- Static-file probe — free, no auth, no AI spend. -->

Ohio AOS direct file URL pattern (no auth):
- `https://ohioauditor.gov/references/SummarizedAnnualFinancialReports/SummarizedReports/City_<YEAR>_<BASIS>_Summarized.XLSX`
- YEAR ∈ 2016..2025 (.XLSX); BASIS ∈ {GAAP, MOD, CASH}. (2013–2015 are older .XLS — out of scope, document as the floor boundary.)
- GAAP workbook = 235 city rows (the spine). CASH/MOD workbooks are smaller (~50KB = far fewer cities file those bases) and hold the cities that DON'T file GAAP — the fallback set for OHCITY-02.
- Probe by HTTP HEAD (or a ranged GET) per (YEAR, BASIS); a 200 + non-trivial content-length means the workbook exists.

Recon-verified Columbus FY2024 GAAP (the GAAP proof target): Total Revenues ≈ 2.166e9; Income Taxes ≈ 1.145e9; Police ≈ 810e6; population 913985.

CASH/MOD proof: download one non-GAAP workbook (e.g. City_2024_CASH_Summarized.XLSX), inspect its SOREACIFB_TotalGov tab, pick any city row present, and dry-run it. The proof is that the SAME buildRevenueTree/buildExpenditureTree/cityPopulation work on the smaller workbook and the basis is correctly tagged — not a specific dollar figure.

Manifest shape (scripts/ohioAosDatasets.json):
{ "entity_type": "city",
  "floor": <earliest fiscal_year present>,
  "datasets": [ { "fiscal_year": 2024, "basis": "GAAP", "url": "https://ohioauditor.gov/.../City_2024_GAAP_Summarized.XLSX" }, ... ] }
One entry per (fiscal_year, basis) that resolves. GAAP preferred as primary; CASH/MOD are the fallback bases.
