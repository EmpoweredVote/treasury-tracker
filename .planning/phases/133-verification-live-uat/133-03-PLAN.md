# Plan 133-03 — PIMA-08 live UAT + PIMA-09 confirmation + close-out

**Mode:** standard
**Goal:** Confirm the whole four-municipality experience live and close the v2.18 milestone. This plan authors the formal UAT checklist (D-06/D-07/D-08), has Chris run it against the live app and sign off (PIMA-08), confirms each live tether icon matches the pre-determined verdict (PIMA-09, D-09), then rolls everything up into `133-VERIFICATION.md` and flips the REQUIREMENTS.md traceability for PIMA-07/08/09. Because the icicle/Money-In render path runs through the external `ev-accounts-api` service, the *visual* render is confirmed by a human here rather than machine-asserted (the DB data shape was proved correct in Phase 132 and independently re-derived in Plan 133-01).

**This plan is not autonomous** — it gates on Chris's live sign-off. The executor authors the checklist and the roll-up scaffolding, then pauses for the human UAT result before finalizing status and traceability.

<threat_model>
No new attack surface: this plan writes only planning/verification markdown + the REQUIREMENTS.md traceability table. No code, no DB writes, no service-role usage, no schema/RPC/frontend change. (The only "risk" is a false-positive sign-off — mitigated by the D-09 predict-then-confirm design and by requiring the machine gates in 133-01/133-02 to have passed before UAT.)
</threat_model>
