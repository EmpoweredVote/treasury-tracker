# Plan 133-02 — PIMA-09: tether verdict pre-determination

**Mode:** standard
**Goal:** Turn the tether check into a *confirmation* instead of a guess (D-09). Before Chris looks at the live banners, compute what the Essentials tethered icon *should* do for each of the four Pima municipalities by fetching the live `coverage.json` and running the same deterministic matcher the app uses. This yields a definitive covered/not-covered verdict per municipality (and guards against a silent match/fetch bug — a mismatch between prediction and live render is itself a finding). For any municipality Essentials doesn't yet cover, this plan documents it as an expected cross-repo coverage gap with a concrete fix pointer (D-10) — no TT code change either way.

Reusable assets: `src/utils/essentialsCoverage.ts` — `matchEntityToCoverage(entity, catalog)` is pure + deterministic; `fetchCoverage()` targets `ESSENTIALS_URL` (`https://essentials.empowered.vote`) and returns `null` on failure. The shipped `scripts/verify-phase130-tether.mjs` already ports this matcher and probes Tucson + Pima County — this plan reuses that probe's structure and extends the entity list to the four new munis (Pima County itself was already confirmed in v2.17 Phase 130). Because `essentialsCoverage.ts` is browser/ESM+Vite `import.meta.env` code, the probe ports the matcher rather than importing the module directly.

<threat_model>
**T-133-02 — Consuming untrusted remote catalog data in the probe.**
- *Surface:* the probe fetches `coverage.json` from a remote origin and reads `label` / `geoids` / `state` fields.
- *Threats:* a malformed or hostile body causing the probe to crash (masking the real verdict) or to emit a false "covered" result.
- *Mitigations:* mirror `isValidCatalogShape` (object + array-typed known fields) before matching; the probe only reads + reports plain data (no URL/DOM/href construction); treat any parse/shape failure as "fetch failed", never as "covered". Read-only; no DB access; no writes to production.
- *Block on:* none (read-only, off-repo) — but a probe crash must surface as "fetch failed", not a silent pass.
</threat_model>
