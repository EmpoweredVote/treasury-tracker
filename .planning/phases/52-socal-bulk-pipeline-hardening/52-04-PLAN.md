# Plan 52-04 — Runbook + end-to-end dry-run proof

**Mode:** standard
**Goal:** Make the hardened pipeline genuinely repeatable by documenting the one-command-per-step onboarding sequence (PIPE-04) and proving it generalizes via a dry-run on a non-OC county — so Phase 53 (Orange County) and every future SoCal county is a known, written procedure rather than tribal knowledge. No Orange County data is created in this phase.

<threat_model>
**T-52-04 — A dry-run that accidentally writes, or a runbook that omits the collision/source rules.**
- *Surface:* the validation command runs the real loader; the runbook is the procedure future counties follow.
- *Threats:* (a) forgetting `--dry-run` writes a half-loaded county; (b) the runbook omits the never-overwrite or source-url conventions, so a future operator regresses them.
- *Mitigations:* validation uses `--dry-run --list-cities` only (no import path); the runbook explicitly states the source-url/date convention, the population source, and the never-overwrite behavior as REQUIRED steps; choose a validation county that is non-Orange and not yet loaded so even an accidental write would be additive and obvious.
- *Block on:* medium.
</threat_model>
