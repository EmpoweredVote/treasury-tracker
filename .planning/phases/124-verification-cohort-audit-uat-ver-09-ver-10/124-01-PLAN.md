| conditional in-phase fix → treasury (write) | Only if a delta is a defect; write goes through the loader's guarded never-overwrite path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-01 | Tampering | source PDF fetch (soft-404) | mitigate | Filter fetches by Content-Type: application/pdf + multi-MB payload size, not HTTP status — a soft-404 HTML page must FAIL the check, never silently tie to 0. |
| T-124-02 | Tampering | image/scan year re-derivation (NM FY2022, OK FY2019, SD scans) | mitigate | Re-render+re-OCR (or independent human-verifiable re-transcription) from the source PDF — NEVER read from any loader-embedded static array; flag OCR-independent rows explicitly so the independence is auditable. |
| T-124-03 | Information Disclosure | SUPABASE_SERVICE_KEY | accept | Key read from ../.env.local/../.env only; never inlined in the script or the log. Read-only DB use (write only on a fixed defect). Standing project practice. |
| T-124-04 | Denial of Service | external PDF hosts (21 state sites + CA/FL) flaky | accept | Read-only re-fetch; if a host is intermittently unavailable, re-run (no DB state at risk). NH needs Wayback mirror (known). |
| T-124-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages — harness uses only Node built-ins + existing deps (the 116-harness pattern) + already-present pdftotext/pdftoppm. No install task. |

Read-only DB queries + local PDF re-extraction; the only data-integrity threat is T-124-01/02 (soft-404 or non-independent image re-derivation silently passing) — mitigated by content-type/size filtering and the no-loader-array OCR rule.
