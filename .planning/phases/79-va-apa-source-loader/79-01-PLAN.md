<objective>
Build the one reusable loader for v2.7: `scripts/loadVAComparativeReport.js`, which parses the Virginia APA "Comparative Report of Local Government Revenues and Expenditures" XLSX into the tracker's budget tree for a single locality and writes it to Supabase via the existing budget RPCs. This is the only new tooling for the milestone — Phases 80–81 just iterate it over localities.

Mirror `scripts/loadUtahTransparency.js` (the closest analog): reuse its `importEntityData` write path (the two RPCs + the pre-skip never-overwrite guard + source columns) and its `--dry-run`/CLI shape, swapping the BigQuery fetch for an `exceljs` XLSX parse. Expenditure becomes a function→activity 2-level tree (Exhibit C + C-1…C-8); revenue a source→sub-source 2-level tree (Exhibits B / B-1 / B-2). Parse only raw-dollar columns; per-capita population from each FY's Exhibit H.

Output: the loader script + offline unit tests. No bulk load and no live proof here — proving on Alexandria FY2024 and determining the available fiscal-year range happen in plan 79-02.
</objective>

<!-- The write path is already proven by loadUtahTransparency.js — reuse it verbatim where possible. -->

Write path (mirror Utah loadUtahTransparency.js):
- treasury_ensure_municipality RPC → returns municipality_id (params: name, state, entity_type).
- treasury_sync_city_budget RPC → writes the budget tree (params include p_data_source_name, p_source_url, p_source_date, the tree, total, fiscal_year, dataset_type).
- Never-overwrite guard: SELECT existing (municipality_id, fiscal_year, dataset_type) data_source; if a different source already owns it, SKIP (treasury_sync_city_budget is NOT source-safe — see auto-memory project_sync_city_budget_not_source_safe).

Source stamping (CONTEXT D-05): data_source='Virginia APA Comparative Report'; source_url = the per-FY data.virginia.gov dataset/XLSX URL (passed in / from a manifest — plan 79-02 produces the FY→URL manifest; for this plan accept a --source-url arg or constant); source_date = fetch date.

XLSX shape (recon: auto-memory reference_virginia_apa_comparative_report; sample at _va-recon/fy2024-comparative-report.xlsx):
- Exhibit C: row 5 headers; col 1 = No., col 2 = locality name; function totals are the raw-$ columns (General Government Administration, Judicial Administration, Public Safety, Public Works, Health and Human Services, Education, Parks/Recreation/Cultural, Community Development, Non-Departmental), Total Expenditures, then Population columns. Per-capita/Percent columns interleave between function columns — SKIP them.
- Exhibits C-1…C-8: per-function activity breakdown (the 2nd level of the expenditure tree), keyed by locality.
- Exhibit B (+ B-1 intergovernmental, + B-2 other local taxes): revenue by source; General Property Taxes breaks into Real Property / Public Service Corporations / Personal Property / Machinery & Tools / Merchants' Capital / Penalties / Interest; plus Permits/Fees, Fines & Forfeitures, Charges for Services, Use of Money & Property, Miscellaneous, Total Local Revenue.
- Exhibit H: per-locality demographics; "Population Estimates July <YYYY>" is the per-capita denominator (D-04).

dataset_type mapping: expenditure → 'operating'; revenue → 'revenue'. Tree shape = the standard {n,a,c:[...]} budget tree already used by buildTree in loadUtahTransparency.js.

    - A column-locator helper that finds the raw-$ column for each named field by reading the row-5 header labels, and explicitly SKIPS "Per Capita" / "Percent of Average" / "Percent of Revenue" columns and any cell whose value is a formula object (exceljs returns `{result|formula|richText}` — read `.result` only for raw-$, never the derived columns).
