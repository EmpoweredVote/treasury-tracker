<objective>
Harden `loadToSupabase()` in `scripts/scrapeMaDLS.js` with two independent, crash-safe behaviors so the Phase 38 bulk load (351 cities × 5 FYs × 2 reports) can resume after a failure and accumulate fiscal years correctly:

- LOAD-02: a per-`(report, FY)`-keyed checkpoint file at `scripts/output/ma_dls_progress.json` so a crashed run resumes from the last successfully loaded city (always-on, no flag, per D-03/D-04/D-05).

Also add `scripts/output/` to `.gitignore` (RESEARCH Open Question 2) and validate SC-4 via a dry-run against a cached 351-record JSON.

Purpose: Without the checkpoint, a crash at city 300 forces a restart from city 1 (re-scraping and re-writing). Without the append fix, loading FY2023 after FY2022 silently wipes FY2022 from `fiscal_years`. Both bugs are confirmed in the current code (existing-row branch only `SELECT id` and never touches fiscal_years; no checkpoint exists).

Output: Updated `scripts/scrapeMaDLS.js`, updated `.gitignore`, and a passing dry-run confirming SC-4.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| script → filesystem (ma_dls_progress.json) | JSON read/write; malformed file must not crash the loader |
| script → Supabase (data_sources, RPC) | JS-built fiscal_years array persisted via .update(); RPC writes budget tree |
| script → MA DLS scrape JSON input | Pre-scraped JSON file read at --load time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-04 | Tampering | ma_dls_progress.json corrupted/partial | mitigate | `readProgress()` wraps `JSON.parse` in try/catch returning `{}` — a malformed or missing ledger triggers a fresh start, never a crash |
| T-37-05 | Tampering | fiscal_years overwrite/duplication | mitigate | `Array.isArray` guard + `.includes(fiscalYear)` dedup before `.update()` — no overwrite, no `[2022,2022]` (Pitfall 3, D-07) |
| T-37-06 | Repudiation | which cities loaded for which (report,FY) | mitigate | Per-city `writeProgress` after each success creates a durable, never-deleted load ledger keyed by `report:fy` (D-04) |
| T-37-07 | Information Disclosure | ma_dls_progress.json + scrape JSON in git | mitigate | `.gitignore` adds `scripts/output/`; ledger holds only public DOR codes, no secrets (RESEARCH Security Domain) |
| T-37-08 | Denial of Service | per-record writeFileSync in 351-row loop | accept | ~1-2ms per write is negligible vs DELAY_MS=1500 HTTP delay; synchronous write chosen for crash-safety (Pitfall 1) |
| T-37-SC | Tampering | npm/pip/cargo installs | accept | No package installs — uses node:fs and @supabase/supabase-js already imported. Package Legitimacy Gate N/A (RESEARCH: "No new packages") |
</threat_model>
