<objective>
Build the one reusable loader for v2.9: `scripts/loadMNOSA.js`, which parses the Minnesota Office of the State Auditor "City/County Finances Report" `Governmental Funds` sheet into the tracker's budget tree for a single entity and writes it to Supabase via the existing budget RPCs. This is the only new tooling for the milestone — Phases 90 (cities) and 91 (counties) just iterate it.

Mirror `scripts/loadOhioAOS.js` (the closest analog — the most recent flat-wide-XLSX loader) for the write path verbatim where possible (`getSupabase`, the `findConflictingBudget` never-overwrite guard, `importDataset`, the `cellNum`/`cellText` formula-safe cell readers, the `--dry-run`/`parseArgs` CLI shape, `resolveSourceUrl` from a JSON manifest, `--entity-type` county handling). The DECISIVE difference vs Ohio: MN's source supports real drill-down, so swap Ohio's FLAT 1-level column→leaf transform for a **3-level-where-natural** build driven by `scripts/mnOsaTreeMap.json` (from 89-01) — the closest existing multi-level builder is `loadUtahTransparency.js buildTree`. The OTHER differences: MN is a SINGLE workbook with the accounting basis in a per-row `GAAPInd` column (not separate GAAP/CASH workbooks like Ohio), and the parent county comes from the `ParentEntityName` column (not a separate demographics tab).

Output: the loader script with exported pure parse/tree functions. No bulk load, no offline tests (89-03), no de-risk dry-run proof (89-04) here — just the loader, exercised once against a recon entity to confirm it runs.
</objective>

Write path (mirror loadOhioAOS.js exactly):
- `getSupabase()` — createClient with SUPABASE_SERVICE_KEY guard (errors clearly when missing; --dry-run never calls it).
- `findConflictingBudget(supabase, municipalityId, fiscalYear, datasetType)` — read-only never-overwrite guard; returns the existing row only if a DIFFERENT data_source owns (muni, fy, dataset_type). treasury_sync_city_budget is NOT source-safe (auto-memory project_sync_city_budget_not_source_safe).
- `importDataset(supabase, municipalityId, fiscalYear, datasetType, tree, total, sourceUrl, sourceDate)` — guard, then `treasury_sync_city_budget` RPC with p_data_source_name=DATA_SOURCE_NAME, p_source_url, p_source_date, the tree, total, p_row_count, fiscal_year, dataset_type.
- `treasury_ensure_municipality` RPC params: p_name, p_state='MN', p_entity_type ('city'|'county'), p_population. County loads MUST pass p_entity_type='county' (auto-memory project_utah_loader_entity_type_and_display_names: else a phantom city row is created).
- `cellNum(cell)` returns NaN for formula-without-cached-result / richText (never a raw-$ value); `cellText(cell)` for labels. Reuse verbatim. Skip `[object Object]` formula-cell artifacts (known VA/Ohio gotcha).
- `resolveSourceUrl(fiscalYear, entityType)` — read city_url/county_url for the fiscal year from scripts/mnOsaDatasets.json (mirror Ohio's resolveSourceUrl, keyed by FY + entityType instead of FY + basis).

Source stamping (CONTEXT D-05 / Discretion): `DATA_SOURCE_NAME = 'Minnesota Office of the State Auditor City/County Finances Report'`; source_url = per-FY city_url (or county_url) from the manifest; source_date = fetch date.

3-level tree build (the new part — driven by scripts/mnOsaTreeMap.json, label-matched at runtime):
- Read the entity's single row in `Governmental Funds` (match by the `Entity Name` column; counties may use ParentEntityName/Entity Type='county' per the 89-01 county-layout notes).
- `buildRevenueTree(workbook, entityName, entityType)` -> `{ tree, total }`. Walk mnOsaTreeMap.revenue.groups: each group is a node `{n, a, c?}`; where a group has a `subtotal_label`, its `a` = that workbook subtotal column and its children are placed beneath (3-level for Intergovernmental: group -> Federal/State/Local sub-groups -> grant-type leaves); naturally-shallow groups are flat leaves `{n, a}`. INCLUDE Intergovernmental (D-04). Drop zero/blank nodes. `total` = the `Total Revenues` column (D-05 — NOT `Total Revenues & Other Sources`).
- `buildExpenditureTree(workbook, entityName, entityType)` -> `{ tree, total }`. Walk mnOsaTreeMap.expenditure.functions: function -> sub-function -> {Current, Capital} deepest leaves where both exist (D-02); functions with only current+capital go function -> {Current, Capital}. `total` = the `Total Expenditures` column (D-05 — NOT `& Other Uses`). The cross-function `Total Current Expenditures`/`Total Capital Outlay` rollups are validation-only (mnOsaTreeMap.expenditure.validation_only_totals) — do NOT place them as nodes (double-count hazard, D-03).
- Double-count guard (D-03): for any group with a subtotal_label, recompute the sum of its placed children and assert it ties to the workbook subtotal within a small tolerance; never sum BOTH a subtotal and its component leaves into the same parent.
- `entityPopulation(workbook, entityName, entityType)` -> Population column value (null if absent). `entityCounty(workbook, entityName, entityType)` -> ParentEntityName column value ('' if absent; used by Phase 91 linking — read+export, not used to write here).
- `entityBasis(workbook, entityName, entityType)` -> 'GAAP' | 'Cash' derived from the GAAPInd column of THAT entity's row (D-07). No cross-workbook fallback.

Tree shape = the standard nested budget tree {n, a, c:[{n, a, c?:[{n, a}]}]} (variable depth, D-01); leaves are {n, a}. dataset_type mapping: expenditure -> 'operating'; revenue -> 'revenue'. p_row_count = top-level node count (mirror Ohio's tree.length).

CLI (parseArgs, mirror loadOhioAOS.js): `--file <path>`, `--entity <name>` (alias `--city`), `--fy <YYYY>`, `--entity-type <city|county>` (default city), `--source-url <url>` (else resolved from manifest), `--source-date`, `--dry-run`. Basis is AUTO from GAAPInd (no --basis flag — that is the MN simplification over Ohio).
