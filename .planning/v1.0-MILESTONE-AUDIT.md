## Critical Gaps

### 1. Donate Button Removed (UI-01, UI-02, UI-03) — BLOCKER

**What happened:** Commit `5604493 fix(ui): remove Donate button from year selector toolbar` removed the donate button. Grep for `Donate`, `givebutter.com`, `donate` across all `src/*.{ts,tsx}` returns zero matches.

**Impact:** The primary user-facing entry point to the donation flow does not exist. A user on financials.empowered.vote cannot initiate a donation from the page. Steps 1–3 of the E2E happy path are broken.

**Note:** The webhook backend (Phase 3) and animated UI (Phase 4) are fully functional once a donation occurs — the middle and end of the pipeline work. Only the initiator is missing.

### 2. Phase 1 → Phase 4 Integration Link Severed

The planned flow was: Donate button click → `handleDonateClick` arms one-shot `visibilitychange` listener → donor returns → revenue refetches. This design was intentional — the listener only fires for users who actually clicked Donate.

What replaced it: The listener now arms on mount via `useEffect` in `App.tsx` lines 327–348 (deps: `[selectedEntity, selectedYear]`). It fires on any tab return for any nonprofit entity on the financials host — not just post-donation returns.

## Tech Debt

### Phase 4: Live Feedback UI

- **UI-04 trigger gate removed** — `visibilitychange` listener arms on mount for any nonprofit entity on financials host. Without a Donate button to re-add, this is the only sensible behavior, but it means any tab-return triggers one revenue refetch even if the user didn't donate.
- **Counter duration 600ms vs spec ~1000ms** — Minor delta. `useAnimatedCounter` default duration is 600ms; REQUIREMENTS.md says "~1000ms". Acceptable.

### Phase 3: Webhook Backend

- **Stale log labels** — `supabase/functions/givebutter-webhook/index.ts` lines 58–62: log object uses `amountCents: amount` and `amountDollars: amount / 100` labels, but amount is actually in dollars. `p_amount: amount` (line 126) correctly passes dollars — this is a logging defect only, not a runtime defect.

### Process

- **Missing VERIFICATION.md for Phases 03 and 04** — gsd-verifier was not run for either phase. Functional confidence is high from live evidence (real $1 test, visual user approval), but formal verification artifacts do not exist.
