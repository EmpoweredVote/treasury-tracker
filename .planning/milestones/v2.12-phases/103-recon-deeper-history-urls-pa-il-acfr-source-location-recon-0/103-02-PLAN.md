# Plan 103-02 — PA + IL ACFR source location

**Mode:** standard
**Goal:** Locate the Pennsylvania + Illinois ACFR Governmental Funds *Statement of Revenues, Expenditures and Changes in Fund Balances* (GENERAL FUND column), bookend-tie-confirm the clean FY window via `pdftotext -table`, pin the four risk facts (units / negatives / exact header+statement / FY-end month), document each state's GF-column scope vs its NASBO GF with an accept-relabel recommendation where it diverges, and verify the clean window reaches the recent years (FY2023+FY2024) before recommending the NASBO replacement. Documentation only; no DB writes; $0. Satisfies the PA/IL half of RECON-04.

<threat_model>
**T-103-02 — A mis-scoped or mis-scaled PA/IL GF column flows into Phase 105, tripling a node (TX trap), mis-scaling a node (NY ×millions trap), or stranding the state's recent NASBO years.**
- *Surface:* downloading PA + IL public ACFR PDFs; running pdftotext; recording URLs + FY depth + four facts + scope-vs-NASBO + recent-window verdict.
- *Threats:* (a) extracting the government-wide Statement of Activities instead of the Governmental Funds GENERAL FUND column; (b) missing the reporting units and loading a node 1000× wrong (the NY millions trap); (c) accepting a consolidated "general/general revenue" fund far broader than NASBO GF without flagging the scope (the TX ~3× surprise); (d) recommending the NASBO replacement when the clean ACFR window misses FY2023/FY2024, silently making PA/IL go backward in recency; (e) a soft-404 HTML page saved as ".pdf".
- *Mitigations:* verify exact statement title + "General Fund" column header + units BEFORE extracting (D-05); record scope-vs-NASBO magnitude and recommend accept-relabel only with the magnitude documented (D-04); the recent-window check (D-06) is a must-have gate before any replace recommendation; validate downloads by Content-Type/size; tie each bookend FY's GF total to the printed total.
- *Block on:* high.
</threat_model>
