<objective>
Build the one reusable loader for v2.8: `scripts/loadOhioAOS.js`, which parses the Ohio Auditor of State "Summarized Annual Financial Reports" (Hinkle System) all-cities XLSX into the tracker's budget tree for a single city and writes it to Supabase via the existing budget RPCs. This is the only new tooling for the milestone — Phases 85–86 just iterate it over cities and counties.

Mirror `scripts/loadVAComparativeReport.js` (the closest analog — the most recent exceljs-based loader): reuse its write path verbatim where possible (`getSupabase`, the `findConflictingBudget` never-overwrite guard, `importDataset`, the `cellNum`/`cellText` formula-safe cell readers, the `--dry-run`/`parseArgs` CLI shape), swapping VA's multi-exhibit layout for Ohio's single flat wide table. Ohio's `SOREACIFB_TotalGov` tab is one row per city where the COLUMNS are the categories, so the trees are flat 1-level (no VA-style function→activity sub-level) and the transform is column→leaf.

Output: the loader script + offline unit tests asserting Columbus FY2024. No bulk load happens here — the FY-range sweep, the manifest, and the CASH/MOD-fallback proof are plan 84-02.
</objective>

Write path (mirror loadVAComparativeReport.js exactly):
- `getSupabase()` — createClient with SUPABASE_SERVICE_KEY guard (errors clearly when missing; --dry-run never calls it).
- `findConflictingBudget(supabase, municipalityId, fiscalYear, datasetType)` — read-only never-overwrite guard; returns the existing row only if a DIFFERENT data_source owns (muni, fy, dataset_type). treasury_sync_city_budget is NOT source-safe (auto-memory project_sync_city_budget_not_source_safe).
- `importDataset(supabase, municipalityId, fiscalYear, datasetType, tree, total, sourceUrl, sourceDate)` — guard, then `treasury_sync_city_budget` RPC with p_data_source_name=DATA_SOURCE_NAME, p_source_url, p_source_date, the tree, total, fiscal_year, dataset_type.
- `treasury_ensure_municipality` RPC params: p_name, p_state, p_entity_type, p_population.
- `cellNum(cell)` returns NaN for formula-without-cached-result / richText (never a raw-$ value); `cellText(cell)` for header labels. Reuse these verbatim.

Source stamping (CONTEXT D-05 analog): `DATA_SOURCE_NAME = 'Ohio Auditor of State Summarized Annual Financial Reports'`; source_url = the per-FY+basis direct file URL (passed via --source-url / a manifest — plan 84-02 produces the year×basis manifest; this plan accepts a --source-url arg); source_date = fetch date. Also record the accounting basis (GAAP/CASH/MOD) — pass it through so plan 85 can track mixed-basis-per-city (OHCITY-02).

XLSX shape (recon: auto-memory reference_ohio_aos_financial_data; no sample on disk yet — Task 1 downloads it):
- Direct file URL pattern (no auth, free): `https://ohioauditor.gov/references/SummarizedAnnualFinancialReports/SummarizedReports/City_<YEAR>_<BASIS>_Summarized.XLSX`, BASIS ∈ {GAAP, MOD, CASH}, YEAR 2016–2025. Use the GAAP workbook (235 city rows).
- Tab `SOREACIFB_TotalGov` (Statement of Revenues, Expenditures & Changes in Fund Balances — governmental funds): one flat row per city. Revenue source columns (≈12): Property Taxes, Income Taxes, Payments In Lieu Of Taxes (PILOT), Special Assessments, Intergovernmental, Interest, Licenses & Permits, Fines & Forfeitures, Rentals, Charges For Services, Contributions/Donations, Other → "Total Revenues". Expenditure function columns (≈18): Police, Fire, Public Services, Health, Leisure Time Activities, Community/Economic Development, Basic Utility Services, Public Works, Transportation, General Government, Intergovernmental, Capital Outlay, Principal Retirement, Interest & Fiscal Charges, Bond/Note Issuance Costs, Other → "Total Expenditures". Below those: Other Financing Sources/Uses + fund-balance lines — EXCLUDE from both trees (D-04b).
- Tab `OI_Demographics`: Population per city (Columbus 913,985) + a `County` column (used by Phase 86 linking, not this plan).
- Recon-verified Columbus FY2024 (GAAP): Total Revenues ≈ $2.166B, Income Taxes ≈ $1.145B, Police ≈ $810M, population 913,985.

dataset_type mapping: expenditure → 'operating'; revenue → 'revenue'. Tree shape = the standard {n,a,c:[...]} budget tree; here c is empty (flat leaves) under a single root, mirroring how loadVAComparativeReport collapses single-level nodes.
