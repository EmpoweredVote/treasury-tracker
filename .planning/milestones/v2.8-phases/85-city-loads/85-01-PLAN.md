<objective>
Build the Phase 85 bulk-load tooling: add a layout-aware `enumerateCities(workbook)` export to the Phase 84 loader, then add a **batch driver** `scripts/loadOhioAOSBatch.js` that — for one fiscal year — opens the GAAP + CASH + MOD all-cities workbooks, assigns every city its best-available basis (GAAP→CASH→MOD, CONTEXT D-02), and iterates the proven Phase 84 `importCity` write path over the whole roster. Cities absent from every financial tab become a source-gap residual (CONTEXT D-03), never a phantom municipality.

No live bulk load happens in this plan — prove the whole roster parses and assigns correctly via `--dry-run` and lock the behavior with offline tests. The live FY2016–2025 sweep + in-phase verification + the committed residual file are plan 85-02.

Mirror `scripts/loadVAComparativeReportBatch.js` (the proven all-localities batch analog): its `enumerateRoster` → loop-over-the-single-locality-write-path shape is exactly Ohio's, minus VA's section-segmentation, plus Ohio's GAAP→CASH→MOD per-city fallback.
</objective>

Reused verbatim from scripts/loadOhioAOS.js (Phase 84, shipped + verified):
- `detectLayout(workbook)` → layout descriptor incl. `sheetName`, `headerRow`, `dataStart`, `entityCol` (GAAP: sheet SOREACIFB_TotalGov, dataStart 8, entityCol 1; CASH/MOD: sheet SORDACIFB_TotalGov, dataStart 7, entityCol 2). Use this for enumeration — do NOT hardcode the tab name or offsets in the driver.
- `cellText(cell)` — whitespace-collapsed text reader (use to read the entity-column name down the rows).
- `buildExpenditureTree`/`buildRevenueTree`/`cityPopulation`/`cityCounty` — per-city extractors (already match by bare entity name).
- `importCity(supabase, workbook, opts)` where opts = `{ cityName, fiscalYear, basis, sourceUrl, sourceDate, dryRun }`. Returns a summary `{ cityName, fiscalYear, basis, operatingTotal, revenueTotal, population, county, expFunctions, revSources, ... }`; with `dryRun:true` it does the full parse and returns the summary WITHOUT touching Supabase. This is the loop body.
- `resolveSourceUrl(fiscalYear, basis)` → the per-FY+basis direct file URL from scripts/ohioAosDatasets.json (null if not in the manifest).
- `getSupabase()` — createClient with the SUPABASE_SERVICE_KEY guard; never called in --dry-run.

New in this plan:
- `enumerateCities(workbook)` (EXPORT from loadOhioAOS.js): call `detectLayout(workbook)`; from `dataStart` down the `entityCol`, collect every non-empty `cellText` entity name that has a finite total (use the layout's revTotalCol or expTotalCol to skip blank/footer rows). Return an array of bare city names in sheet order. Must work for GAAP and CASH/MOD layouts. (Mirrors VA enumerateRoster, minus sectioning.)
- `scripts/loadOhioAOSBatch.js` — the driver (see tasks). Manifest acquisition: for a basis, if the per-basis --file override is given use it; else `resolveSourceUrl(fy, basis)` + download to `_oh-recon/City_<FY>_<BASIS>_Summarized.XLSX` (skip a basis whose URL is null or whose download 404s — that basis simply has no workbook for that FY). _oh-recon/ is already gitignored (Phase 84).

Basis assignment (CONTEXT D-02): build a Map<cityName, {basis, workbook}>. Seed from the GAAP roster (basis 'GAAP'); then for each CASH city not already in the map add {basis:'CASH'}; then MOD likewise. The first-seen (by GAAP→CASH→MOD order) wins. Residual (CONTEXT D-03): union of OI_Demographics city rosters across the opened workbooks minus the financial-tab union = cities with demographics but no financial row.

CLI (parseArgs), mirror loadVAComparativeReportBatch.js shape:
`node scripts/loadOhioAOSBatch.js --fy <YYYY> [--file-gaap <p>] [--file-cash <p>] [--file-mod <p>] [--limit N] [--dry-run]`

Capture per-city errors into a `failures` array (and, for live runs, append to `scripts/load-ohio-cities.failures.txt`) WITHOUT aborting the roster — mirror the VA batch's resilient loop.
