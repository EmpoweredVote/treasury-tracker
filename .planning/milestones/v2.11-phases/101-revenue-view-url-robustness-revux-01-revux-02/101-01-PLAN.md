<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query params (`?dataset=`, `?year=`, `?entity=`) → client routing state | untrusted user-supplied/bookmarked input crosses into `setActiveDataset`/`setSelectedYear` |
| client → API (read-only fetch) | unchanged this phase (no writes; no new endpoints) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-101-01 | Tampering | malicious/garbage `?dataset=` value (e.g. `?dataset=<script>` or `?dataset=foo`) reaching state | mitigate | static allow-list guard (`operating\|revenue\|salaries`) THEN availability check; anything else → 'operating'. Value is only ever used as a keyed enum, never rendered as HTML. |
| T-101-02 | Denial of service (UX) | `?dataset=revenue` on an operating-only node → disabled-but-active empty/broken view | mitigate | resolveEffectiveDataset falls back to 'operating' when revenue is unavailable for the resolved year |
| T-101-03 | Information disclosure | deep-link exposing a dataset an entity should not show | accept | all served data is public-record finance data; availability is the API's published `available_datasets`; no auth/PII boundary involved |
| T-101-SC | Tampering | npm dependency changes | accept | no new dependencies; no new test framework; uses existing build/test tooling only |
</threat_model>
