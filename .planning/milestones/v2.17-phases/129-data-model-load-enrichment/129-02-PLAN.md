# Plan 129-02 — Load Tucson GF operating + revenue

**Mode:** standard
**Goal:** Turn the Phase-128 extractor into live, sourced, navigable data. Build `scripts/processTucson.js`, which runs `extractTucson.py` across the locked FY2015–FY2024 window in both modes, maps the extractor's nested tree to the RPC tree shape (2-level for operating, flat for revenue), and loads through the **source-safe `treasury_sync_budget_tree` RPC** — stamping a durable `source_url`+`source_date` on every row, keeping `data_sources` ephemeral, and re-running idempotently.

Depends on 129-01 (the Tucson municipality must exist). No schema change, no enrichment (Plan 129-03).

<threat_model>
**T-129-02 — Running an external binary over files + privileged bulk writes to shared production budget tables.**
- *Surface:* spawns `extractTucson.py` (which spawns `pdftotext`) over PDFs in `docs/Tucson/`, then bulk-writes `treasury.budgets` via a service-role RPC.
- *Threats:* (a) shell injection via an interpolated path/URL; (b) a silent mis-parse loading wrong numbers; (c) overwriting another source's rows / leaving stale rows on re-run; (d) an out-of-range total indicating a parse blow-up; (e) leaving orphan `data_sources` residue.
- *Mitigations:* `spawnSync` with an **args array** (no `shell:true`); PDF paths come from a controlled `docs/Tucson/` readdir, not user input; **trust the extractor's `tie_delta==0` gate** (non-zero exit aborts the FY) AND independently re-derive the loaded total against the source printed total; use the **source-safe RPC** (`treasury_sync_budget_tree`, never `treasury_sync_city_budget`) with a per-`(data_source_id,fiscal_year)` pre-load delete so re-runs never duplicate or overwrite foreign rows; per-FY sanity ceiling on the total; **ephemeral `data_sources`** (delete at run end).
- *Block on:* high (bad or overwriting writes corrupt a shared production dataset).
</threat_model>
