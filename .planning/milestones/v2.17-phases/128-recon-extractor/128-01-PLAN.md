# Plan 128-01 — Tucson ACFR recon + window lock

**Mode:** standard
**Goal:** Prove the Tucson ACFR source is loadable end-to-end before any code is written against it: enumerate every published year, pin a durable per-year PDF URL, confirm each year's General Fund column bookend-ties its printed totals at $0 via `pdftotext -table`, and lock the deepest contiguous tying window. Output is `128-RECON.md` — the authoritative input for the extractor (Plan 128-02) and every later load.

This plan does **no** code, no seed, no load, no schema touch (Phase 129). It is pure source validation + documentation.

<threat_model>
**T-128-01 — Fetching remote PDFs + running an external binary over network-sourced files.**
- *Surface:* recon downloads PDFs from URLs and pipes them through the `pdftotext` binary.
- *Threats:* (a) fetching an arbitrary/attacker-controlled URL (SSRF / wrong-file), (b) shell injection if a URL or path is interpolated into a shell string, (c) trusting a filename pattern that silently 404s or returns an HTML error page saved as `.pdf`.
- *Mitigations:* restrict fetches to the **`tucsonaz.gov` host** (known ACFR archive); before pinning any URL, verify it returns **HTTP 200 with `Content-Type: application/pdf`** (reject HTML error pages); invoke `pdftotext` with an **args array** (no shell string, no `shell=True`); write only into the controlled `docs/Tucson/` directory.
- *Block on:* medium. Do not pin a URL that fails the 200/PDF check; document it as a hole instead.
</threat_model>

<task id="128-01-01" type="execute">
<action>
Enumerate the published Tucson ACFR years and pin a durable per-year PDF URL for each. Start from the archive index page `https://www.tucsonaz.gov/Departments/Business-Services-Department/Accounting-and-Finance/Annual-Comprehensive-Financial-Reports` and the known FY2024 direct URL `https://www.tucsonaz.gov/files/sharedassets/public/v/1/bsd/documents/finance-documents/cot-2024-annual-comprehensive-financial-report.pdf`. The apparent per-year pattern is `cot-<YYYY>-annual-comprehensive-financial-report.pdf`, but DO NOT assume it holds for older years — for each candidate year, verify the URL resolves with HTTP 200 and `Content-Type: application/pdf` (host must be tucsonaz.gov). Download each resolvable PDF into `docs/Tucson/` keeping the source filename. Record each year, its durable URL, HTTP status, and file size. Any candidate year whose URL 404s or returns non-PDF is noted (not pinned) for the holes list in 128-01-03.
</action>

<task id="128-01-02" type="execute">
<action>
For each downloaded ACFR, locate the governmental-funds **Statement of Revenues, Expenditures and Changes in Fund Balances** page and extract it with `pdftotext -table` (args array; NEVER `-layout` — it scrambles the multi-fund columns). Reading the **General Fund column (the first data column)**, bookend-tie the year: sum the printed GF revenue-source rows and confirm the sum equals the printed `Total revenues` at exactly $0; sum the printed GF expenditure-function rows and confirm the sum equals the printed `Total expenditures` at exactly $0. Cross-check `Total revenues − Total expenditures == printed Excess (deficiency)`. Record the statement page number and both tie deltas per year. A year whose statement is absent, image-only, or in a pre-format layout that will not `-table`-tie is recorded as a non-extractable hole with the specific reason.
</action>

- .planning/phases/128-recon-extractor/128-RESEARCH.md (§2 tree shapes; §3 landmines — wrapped label, $/blank cells, parens, sub-total rows; §6 tie definitions)
- scripts/processAZAcfr.js (how the state loaders spawn `pdftotext` with an args array and tie the GF column to the printed total)
- docs/Tucson/ (the PDFs downloaded in 128-01-01)
</read_first>
<acceptance_criteria>

</acceptance_criteria>
</task>
