# Plan 128-02 — `extractTucson.py`

**Mode:** standard
**Goal:** Build the programmatic extractor that turns each windowed Tucson ACFR PDF into the two General Fund trees (revenue-by-source; 2-level expenditure-by-function) and **self-ties** each tree to the printed GF total at $0. This is the only genuinely new code in the milestone. It consumes the window and URLs locked in Plan 128-01 and produces the trees Phase 129 will load via `treasury_sync_budget_tree`.

No seed, no live load, no schema touch — the extractor only reads local PDFs and prints JSON.

<threat_model>
**T-128-02 — Parsing network-sourced PDFs; a malformed/hostile PDF could produce wrong-but-plausible numbers or inject via the subprocess.**
- *Surface:* `extractTucson.py` shells out to `pdftotext` and parses its text output into financial trees that Phase 129 loads into the app-facing `treasury.budgets`.
- *Threats:* (a) command injection via a crafted path/filename, (b) a mis-parsed row silently producing a tree that looks right but is wrong, (c) column bleed from the adjacent Mass Transit / Total columns inflating GF numbers.
- *Mitigations:* invoke `pdftotext` with an **args array** (`subprocess.run([... ], shell=False)`), pass paths as list elements (no interpolation); make the **$0 `tie_delta` the hard gate** — a non-zero delta exits non-zero so a mis-parse can never pass silently downstream; read GF strictly as the **first data column** and validate parent sub-totals equal the sum of their children (a second independent tie that catches column bleed).
- *Block on:* high (the tie gate). A tree that does not tie $0 must not be emitted as valid.
</threat_model>

Create `scripts/extractTucson.py` mirroring the `extractGresham.py` CLI contract: `argparse` with positional `pdf_path`, `--mode {operating,revenue}` (default `operating`), JSON printed to stdout, warnings to stderr. Replace pdfplumber with a `pdftotext -table` subprocess (args array, `shell=False`) that renders the governmental-funds statement page(s) to text. Implement a shared column-reader that locates the header row (`General Fund` ... `Total Governmental Funds`), treats **General Fund as the first data column**, and for each row returns (label, gf_value) — buffering label-only lines so the wrapped "Community enrichment and / development" row rejoins its number, and ignoring `$`/blank cells belonging to the other fund columns.
</action>

<task id="128-02-02" type="execute">
<action>
Implement `--mode revenue`: build a flat GF revenue-by-source tree from the printed sources (Taxes, Other agencies, Charges for services, Licenses and permits, Use of money and property, Miscellaneous, Fines and forfeitures, Federal grants, Contributions, Developer fees — label-driven, not count-locked). Capture the printed `Total revenues` as the tie target but exclude it from the leaves. Implement `--mode operating`: build the 2-level expenditure tree — parents `Current` (children: Public safety & justice, Community enrichment & development, Support services, General government, Elected & official) and `Debt service` (children: Principal, Interest, Fiscal agent fees), plus top-level leaves `Capital outlay` and `Capital projects`; capture printed `Total expenditures` as the tie target and exclude sub-total/bookend rows from the tree. Emit JSON `{ fiscal_year, mode, tree, computed_total, printed_total, tie_delta }`. `tie_delta = computed_total - printed_total`; if `tie_delta != 0`, print the offending rows to stderr and exit non-zero. For operating mode, also assert each parent's printed sub-total equals the sum of its children (report mismatch, non-zero exit).
</action>
