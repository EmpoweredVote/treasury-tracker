# Plan 60-03 — reconciliation + coverage documentation (salaries closeout)

**Mode:** standard
**Goal:** Close out the statewide salaries sweep with **light inline checks** (D-09 carry-forward): one
sample-city ~$0-delta reconciliation, a per-city coverage/gap table from the sweep results JSON, and a
single live-app render spot-check. Formal multi-city reconciliation + full source-chain audit + Chris UAT
remain Phase 62. Satisfies SC#3 + SC#4 and SAL-06. Read-only: DB probes + the results JSON + one live
spot-check; no data writes, no new source files.

**Scope discipline:** sampled sanity pass, NOT exhaustive reconciliation. Reconcile ONE representative
city; document coverage from the artifact 60-02 already produced; spot-check ONE city's render. Anything
heavier is Phase 62.

<threat_model>
**T-60-03 — Verification gives a false PASS: reconciles against a self-derived figure (circular), mis-reads the coverage JSON, or the render check passes on stale/wrong data.**
- *Surface:* read-only — DB probes, the sweep results JSON, one live spot-check. No write surface.
- *Threats:* (1) the reconciliation "published" figure is just the same GCC sum recomputed (proves nothing); (2) the coverage table miscounts gaps or conflates expected gaps with load failures; (3) the live render check confirms the page loads but not that salaries data actually appears.
- *Mitigations:* (1) reconcile the DB total against an INDEPENDENT published reference — the city's GCC profile on publicpay.ca.gov or a published payroll total — not a re-sum of the same ingested rows; state the source of the published figure; (2) cross-check the coverage table against both the results JSON and a direct DB count, and label expected-gap cities distinctly from any failed-year retries; (3) the render check must confirm a salaries figure/department tree is visible for the city, not merely that the page renders.
- *Block on:* none (read-only) — but a reconciliation delta beyond ~$0 tolerance, or a coverage shortfall, blocks marking the phase ready for Phase 62 and is recorded with a reason.
</threat_model>
