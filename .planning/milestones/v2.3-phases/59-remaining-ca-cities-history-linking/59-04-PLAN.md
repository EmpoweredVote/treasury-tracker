# Plan 59-04 — light inline verification (parity closeout)

**Mode:** standard
**Goal:** Confirm the four phase success criteria hold via **light inline checks only** (D-09, carried forward from Phase 58 D-09): FY-reach + source chips on a sample, links + breadcrumb + Cities-in-County render live, SF combined-node renders clean, custom cities untouched, Test gone, basis note renders. Formal ACFR reconciliation + full source-chain audit + Chris UAT remain **Phase 62**. Covers HIST-02 + ENR-02 closeout.

**Scope discipline:** this is a sampled sanity pass, NOT exhaustive reconciliation. Sample one or two representative cities per check rather than every city. Anything heavier (per-figure ACFR matching, full source-chain audit, user acceptance) is explicitly Phase 62 and must NOT be attempted here. Read-only: DB probes + live-app spot-checks; no data writes, no new source files. This plan records findings in its summary; it does NOT author a VERIFICATION.md (that is the verify-phase / Phase 62 artifact).

<threat_model>
**T-59-04 — Verification gives a false PASS (checks the wrong thing or misses a regression).**
- *Surface:* read-only probes/spot-checks only — no write surface.
- *Threats:* a green check that misses a NULL source_url on a layered row, a never-overwrite regression on a custom or rich city, a "San Francisco County" node that slipped in (D-07 violation), a Test record that survived, or a basis-note misfire.
- *Mitigations:* checks are concrete (exact FY reach, `/d/<id>` source_url present, baseline equality for the rich + custom cities, no SF county node, Test absent, note present/absent per city); any failure routes back to the owning plan (59-01/02/03) rather than being waved through.
- *Block on:* none (read-only) — but a failed criterion blocks marking the phase ready for Phase 62.
</threat_model>
