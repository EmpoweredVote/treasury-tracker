# Plan 58-02 — LA County government budget backfill (FY2003–2024)

**Mode:** standard
**Goal:** Execute **Step 5** of `docs/socal-county-onboarding.md` for Los Angeles County: backfill the county-government's own operating + revenue to **FY2003–2024** via the existing `scripts/loadCountyBudget.js --county "Los Angeles" --entity "Los Angeles County"` (SCO ByTheNumbers county datasets uctr-c2j8 / emxv-k8xv, all-governmental-funds basis), matching Orange County's depth. This adds FY2003–2020 and **re-syncs FY2021–2024** to repair their NULL `source_url`. Satisfies LAC-01.

**Why a full reload is safe (verified, D-06):** `loadCountyBudget.js:72/78` writes `data_source = "CA State Controller - County Expenditures/Revenues"` — the *exact* labels on the existing LA County FY2021–2024 rows. Its `findConflictingBudget` (:209-224, mirroring the city loader) preserves a row only when its `data_source !== ` the loader's own label; same label ⇒ re-sync via `treasury_sync_city_budget` with `p_source_url = ds.pageUrl`. So FY2021–2024 are refreshed (source_url repaired), FY2003–2020 load fresh. SCO county datasets end at FY2024 ⇒ no FY2025 (the existing FY2025 LA County row is **salaries**, a different dataset_type, untouched here).

**Entity (D-07):** `loadCountyBudget.js` resolves the existing "Los Angeles County" entity (`entity_type='county'`, `ilike` name) and **errors if not found** — it never ensure-creates with a population. The entity already exists with population 10,014,009; population backfill is write-only on 0/NULL, so that value is preserved.

**Load shape:** dry-run → confirm SCO entity_name + clean re-sync classification → **canary FY2024** (already present — proves source_url repair, basis, county-only writes) → verify → **backfill FY2003–2023 in ≤2-year submits** (the 57-01 proven pattern). Idempotent on (municipality_id, fiscal_year, dataset_type).

<threat_model>
**T-58-02 — A county backfill writes to the wrong entity, clobbers the cities/salaries, or leaves figures unsourced.**
- *Surface:* `loadCountyBudget.js` writes county budget rows via the service-role key. A wrong entity resolve (matching a city or a duplicate county), an over-broad SCO `$where`, or a label mismatch could overwrite city rows or the salaries dataset, or leave source_url unrepaired.
- *Threats:* (1) destruction of the 88 LA County city rows or the county salaries (FY2021–25); (2) FY2021–2024 left with NULL source_url if unexpectedly skipped; (3) population reset to 0 breaking per-capita; (4) an unsourced load.
- *Mitigations:* (1) the loader resolves the EXISTING county entity by exact `--entity "Los Angeles County"` (`entity_type='county'`) and errors if absent — never ensure-creates with a population (:167-192); (2) SCO `$where` is `entity_name='<county>' AND fiscal_year=<fy>` — a single entity; (3) never-overwrite pre-pass skips any other-source row (:269-274); (4) salaries are a different `dataset_type` (operating/revenue only here) so they are out of scope of every write; (5) every write passes `p_source_url` (durable `/d/<id>`) + `p_source_date`; (6) canary-before-backfill gate; (7) final verify confirms the 88 city rows + the salaries dataset are unchanged.
- *Block on:* high. Do not run the backfill (task 04) until the canary (task 03) verifies source_url repaired, basis-matched total, population intact, and cities/salaries untouched.
</threat_model>
