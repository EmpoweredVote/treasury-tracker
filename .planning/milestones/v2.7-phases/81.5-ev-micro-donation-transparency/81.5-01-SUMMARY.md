## Decisions Made

- **Benevity = 1 donor (hard rule):** 61 disbursement rows represent exactly one real person (Chris Andrew's Cisco volunteer-match recurring giving). Hard-coded with comment per Phase 81.5 memory guardrail.
- **Median over GiveButter + Patreon only:** Benevity's company-match (~$368/mo equivalent) is atypical and would skew the "micro-donation story" median if included.
- **Most-recent charge as typical monthly:** For donors with variable amounts (one GB donor had $100 for 3 months then $25), the most-recent charge is the best representation.
- **Lean carrier approach:** No backend schema change; `item_count` and `description` fields already returned by the API — frontend (Phase 81.5-02) parses the `_evMicro` JSON.
