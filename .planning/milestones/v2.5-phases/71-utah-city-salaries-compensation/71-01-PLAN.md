<objective>
Extend the proven Phase 68–70 `loadUtahTransparency.js` loader to load **names-free employee compensation** (`PY` → `dataset_type='salaries'`) for the **10 Utah cities** for every complete fiscal year (FY2014–FY2025, FY2026 excluded), then sweep all 10 cities and reconcile one against the Transparent Utah Compensation Downloader (USAL-01).

The loader currently **skips** `PY` (`main` bails with a warning even though `typeToDataset('PY')='salaries'`). The new PY path MUST be **aggregate-only and names-free** (D-71-01): the BigQuery query SELECTs only `org1, cat1, SUM(amount)` — never a PII column — and the tree is a **2-level** Department(`org1`) → comp-category(`cat1`: Wages/Benefits) tree (D-71-02) in the same compact shape the app's existing CA-GCC salaries view consumes (`{n,a,c:[{n,a}]}`, top=dept, leaves=categories, no third `i` level). An automated unit test must FAIL if any PII column name leaks into the query or the tree.

Purpose: complete the v2.5 Utah municipal expansion's salaries dataset at full CA parity, $0, with a public-record-only safety line (structural department/category accountability, never individual names).
Output: the loader's PY path + PII guard test, all 10 cities' salaries loaded FY2014–FY2025, ≥1 city reconciled, per-city coverage/gaps documented, and a live-app render spot-check — with all operating/revenue budget rows untouched.
</objective>
