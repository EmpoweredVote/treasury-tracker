## Milestone Summary

**Decimal Phases:** None

**Key Decisions:**

- max_tokens=8192 — sufficient for dense ACFR page (~40 rows × ~200 tokens); 64k unnecessary and costly
- stop_reason guard returns without retry — truncation is deterministic
- pct_unknown as re-extraction metric, not total row count (Haiku is non-deterministic)
- Plano FY2023–FY2026 skipped — 0.1% marginal gain, ~$20 API cost not justified for unfunded nonprofit
- ACFR revenue extraction limitation — vision cannot separate revenue statements from capital/balance sheet pages; future approach: pdftotext + text-marker targeting of "STATEMENT OF REVENUES" section
- Cost gating rule — document skipped runs explicitly when marginal quality gain doesn't justify API spend
- Richardson skip accepted — cor.net HTTP block is infrastructure constraint, not data quality gap; placeholder infrastructure seeded for future manual load

**Issues Resolved:**

- "Unknown" department dominance in PDF-extracted budgets (root cause: max_tokens truncation + no cross-page context)
- Exit code 2 JSON truncation on dense statistical ACFR pages
- Frisco placeholder categories (31 XLSX-derived) replaced with 1,416 real PDF-extracted categories
- Princeton MA/TX duplicate data_source rows — MA placeholders deleted 2026-05-21

**Issues Deferred:**

- REV-05 Prosper revenue — pdftotext + STATEMENT OF REVENUES text-marker approach needed
- REV-06 Celina revenue — same approach as Prosper
- COL-02 Richardson — manual browser URL sourcing from https://www.cor.net/departments/budget required before load

**Technical Debt Incurred:**

- Plano FY2023–FY2026 remain at 0.1% unknown (1 row/year) — cost-justified skip; re-run at ~$5/year if needed
- bulkLoadPDF.js line 144 has TODO for chunked rendering (OOM concern for very large PDFs) — future optimization
