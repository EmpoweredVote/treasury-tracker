|----------|-------------|
| loadCASalaries.js → production Treasury DB | A 34-city × multi-year sweep writes many `salaries` rows via the service key — the heaviest write in the milestone. Wrong city resolution or wrong dataset_type could mis-attach or overwrite data. |
| external GCC source → coverage truth | Thin/absent coverage for some cities must be recorded as a gap, not fabricated or back-filled (D-06 / never-fabricate). |
| salaries write vs existing custom-sourced rows | Anaheim/Santa Ana operating/revenue are custom-sourced; the additive salaries load must not disturb them. |

| T-55-03-03 | Tampering | Wrong municipality resolution → salaries on the wrong city | mitigate | OC city set is read from the DB via county_id (Phase 54); treasury_ensure_municipality resolves existing cities; Task 2 reconciliation + Task 3 live check confirm correctness. |
