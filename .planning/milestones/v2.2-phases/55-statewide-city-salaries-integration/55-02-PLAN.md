<objective>
Build the SAL-02 deliverable: a single **reusable, city-parameterized** statewide salaries
loader, `scripts/loadCASalaries.js`, that imports employee compensation for ANY California
city from the GCC source (gcc.sco.ca.gov) confirmed by the Plan 55-01 spike. It generalizes
the LA-only `scripts/loadLACountySalaries.js` (which read an LA-specific ArcGIS FeatureServer)
into a statewide loader reading the publicpay.ca.gov raw CSV export, with the city as a CLI
argument and nothing OC-specific hard-coded.

The write path is reused unchanged: it builds the compact `n/a/c/i` Department → Position tree
(Position is the leaf — NO individual names, D-01), sums on **Total Compensation = wages +
employer benefits** (D-02), carries the wages/benefits metadata split per position (D-03), and
writes a `salaries` budgets row via `treasury_sync_city_budget` after resolving the city's
existing municipality via `treasury_ensure_municipality`.

This plan PROVES the loader on ONE OC city (dry-run + a single real load) and reconciles the
loaded total against the published source figure. The full OC sweep + gap documentation is
Plan 55-03.

**Precondition:** Plan 55-01's GATE verdict is PASS (operator-approved). Read 55-SPIKE-FINDINGS.md
for the exact download URL pattern, client/User-Agent, and field mapping — do not re-derive them.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| loadCASalaries.js → external gcc.sco.ca.gov | The loader downloads CSV from an external State Controller server. Malformed/ambiguous columns or a changed export schema could corrupt the tree or totals. |
| loadCASalaries.js → production Treasury DB | The loader writes `salaries` budgets rows via the service key. A wrong municipality resolution or wrong dataset_type could overwrite or mis-attach data. |
| raw rows → published data (D-01 safety line) | If a name column slipped into leaf items, the app would display PII against the no-targeting ground rule. |
| salaries write vs existing custom-sourced cities | Anaheim/Santa Ana operating/revenue are custom-sourced; salaries is a different dataset_type but the never-overwrite convention still binds. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-02-01 | Information disclosure | Individual names / PII reaching leaf items | mitigate | Loader defaults to no-names with no names-on path; buildTree never pushes a name field onto position leaves (Position IS the leaf, D-01); Task 3 DB probe confirms no name leaf items in the stored tree. |
| T-55-02-02 | Tampering | Wrong municipality_id → salaries attached to the wrong city, or a duplicate municipality created | mitigate | treasury_ensure_municipality resolves the existing OC city (Phase 53/54) by name/state; Task 3 probe confirms the row lands on the expected municipality_id; loader never hard-codes OC ids. |
| T-55-02-03 | Tampering | Overwriting a city's operating/revenue or custom-sourced rows | mitigate | Loader writes ONLY p_dataset_type='salaries'; salaries is additive and orthogonal to operating/revenue; Task 3 asserts other dataset rows untouched. |
| T-55-02-04 | Denial of correctness | Wrong column mapping / wrong Total Compensation aggregation | mitigate | Field mapping is taken from the spike findings (reconciled in 55-01); Task 3 re-reconciles the loaded total against the published figure (SC-4) before scaling. |
| T-55-02-05 | Spoofing / integrity | Building before the spike gate passed | mitigate | Task 1 asserts `GATE: PASS` in 55-SPIKE-FINDINGS.md and stops otherwise (D-05 hard gate). |
| T-55-02-SC | Tampering | npm package installs | accept | No new packages — reuses @supabase/supabase-js + node built-ins already in the repo; no `npm install` step. (If a zip/CSV parse needs a dep, flag for manual approval — prefer node built-ins.) |
</threat_model>
