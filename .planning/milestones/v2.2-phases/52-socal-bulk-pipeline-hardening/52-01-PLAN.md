# Plan 52-01 — City-budget source attribution primitive

**Mode:** standard
**Goal:** Make the city-budget write path able to persist a durable source URL and a fetch date, so every figure the hardened pipeline loads meets the same always-sourced bar as federal (CONTEXT D-02..D-04). This is the only DB/RPC change in the phase and the only human-gated step — additive and backward-compatible.

<threat_model>
**T-52-01 — Editing a shared write-path RPC regresses existing city/state/federal data.**
- *Surface:* `treasury_sync_city_budget` is called by `bulkLoadStateController.js` today and is the shared per-city budget writer; `treasury.data_sources` and `treasury.budgets` are read live by treasurytracker.empowered.vote.
- *Threats:* (a) changing the signature breaks existing 7-arg calls; (b) the edit alters how the data_sources row is created/linked and corrupts existing source chips; (c) applying to production without review.
- *Mitigations:* add `p_source_url`/`p_source_date` as TRAILING params with `DEFAULT NULL` so all existing calls keep resolving; only write the new columns when the params are non-NULL (existing rows untouched); read the live body with `pg_get_functiondef` and edit in place (CREATE OR REPLACE) rather than rewriting from scratch; **human checkpoint before apply**; post-apply probe confirms an existing FY2025 city source chip is unchanged.
- *Block on:* high. Do not apply without the GO checkpoint.
</threat_model>
