seedCountyLinks.js CLI (run, do not edit):
  node scripts/seedCountyLinks.js --county "Orange" [--state CA] [--dry-run] [--force]
  - County name MUST be exactly "Orange" (no "County" suffix) — matches the SCO `county` field.
  - Derives membership from SCO ByTheNumbers expenditures dataset ju3w-4gxp (same feed the loader uses).
  - Step 1: reuses an existing "Orange County" entity (entity_type='county', state='CA') if present;
    creates it once via RPC treasury_ensure_municipality otherwise. Never duplicates.
  - Step 3 (link): sets municipalities.county_id ONLY where it is NULL or already this county.
    A city already linked to a DIFFERENT county is reported "Skipped — linked to another county"
    and is NOT repointed unless --force is passed.
  - Cities returned by SCO but absent from the DB are reported "Not yet in DB — load budget first".
  - Linking NEVER reads or writes treasury.budgets / budget_line_items / data_source — budget data is untouched.
  - Summary lines printed: "Would link / Linked (N)", "Already linked (N)", "Skipped — linked to another county (N)", "Not yet in DB — load budget first (N)".

DB access (production Treasury DB — NOT mcp__supabase-local, which is a different/social DB):
  - Uses repo .env: SUPABASE_URL (defaults to https://kxsdzaojfaibhuzmclfq.supabase.co)
    + SUPABASE_SERVICE_KEY or SUPABASE_SERVICE_ROLE_KEY.
  - Tables in schema `treasury`: municipalities (id, name, state, entity_type, county_id, population),
    budgets (municipality_id, fiscal_year, dataset_type, total_budget, data_source...).
