# Plan 57-01 — Reusable county-budget loader + load Orange County's own budget

**Mode:** standard
**Goal:** Execute **Step 5** of `docs/socal-county-onboarding.md` for Orange County: generalize the LA County one-off loaders into one reusable `scripts/loadCountyBudget.js`, then load the OC county-government **operating + revenue** budget (SCO ByTheNumbers *county* datasets, all-governmental-funds basis) onto the existing OC county entity seeded in Phase 54 — with durable source attribution and a working per-capita population. Satisfies OCB-01.

**Load shape (CONTEXT D-05, from Phase 53):** a single 22-year run risks the 600s command timeout. So: build → dry-run → **canary FY2024** end-to-end → verify → **backfill FY2003–2023 in ≤2-year submits** → full verify. Writes are idempotent on (municipality_id, fiscal_year, dataset_type) via `treasury_sync_city_budget`, so any chunk is safe to re-run.

**Basis (Phase 56 finding):** SCO county totals are **all-governmental-funds**, not General Fund. That is the loaded figure; the basis is documented in the load output and (Plan 57-02) in `57-VERIFICATION.md`.

<threat_model>
**T-57-01 — A county-government load clobbers the county's or the 34 cities' existing data, or writes unsourced/mis-targeted figures.**
- *Surface:* `loadCountyBudget.js` resolves a municipality by name and writes budget rows via the service-role key. A wrong entity lookup (e.g. matching a city, or ensure-creating a duplicate county with a clobbering population), an over-broad SCO `$where`, or a missing collision check could overwrite the 34 cities' ByTheNumbers/custom rows (Anaheim, Santa Ana) or reset the county population to 0.
- *Threats:* silent destruction of city/county detail; an unsourced load (no `source_url`/`source_date`) violating the always-sourced ground rule; a partial/timed-out backfill that still "looks" done; per-capita broken by a 0 population.
- *Mitigations:* (1) resolve the **existing** county entity by exact name/`--entity` (`entity_type='county'`) and **error if not found** — never ensure-create with a population that clobbers; (2) SCO `$where` is `entity_name='<county>' AND fiscal_year=<fy>` — a single entity, never county-wide; (3) a never-overwrite pre-pass mirroring `bulkLoadStateController.js:findConflictingBudget` skips/logs any pre-existing other-source row; (4) population backfill is write-only when 0/NULL (never lower a non-zero pop); (5) every write passes `p_source_url`(durable `/d/<id>` page) + `p_source_date`; (6) canary-before-backfill gate (task 03 must verify clean before task 04); (7) final verify confirms the 34 cities' rows are byte-for-byte their prior `data_source`.
- *Block on:* high. Do not run the backfill (task 04) until the canary (task 03) verifies clean source attribution, population, a matched spot-total, and 34 cities untouched.
</threat_model>

<task id="57-01-01" type="execute">
<action>
Build the reusable loader `scripts/loadCountyBudget.js`. Generalize the LA County one-offs into ONE script that loads operating + revenue for a single county-government entity. Concrete requirements:

- CLI args (`node:util` parseArgs, `strict:false`): `--county` (SCO `entity_name` filter, e.g. `"Orange"`), `--entity` (DB municipality name override; default `"<county> County"`), `--fy` (repeatable), `--type` (`operating`|`revenue`; default both), `--population` (integer sourced fallback), `--source-date` (default today, computed ONCE per run), `--dry-run`.
- Datasets map: `operating` → id `uctr-c2j8`, label `CA State Controller - County Expenditures`, pageUrl `https://bythenumbers.sco.ca.gov/d/uctr-c2j8`; `revenue` → id `emxv-k8xv`, label `CA State Controller - County Revenues`, pageUrl `https://bythenumbers.sco.ca.gov/d/emxv-k8xv`.
- Fetch: `$where = entity_name='<county>' AND fiscal_year=<fy>` (escape `'` → `''`), paged like `loadLACountyOperating.js` (`$limit`, `$order: category,subcategory_1,subcategory_2`).
- Reuse `parseAmt` and `buildTree` (category → subcategory_1 → line items via subcategory_2/line_description) VERBATIM from `loadLACountyOperating.js` — same compact `{n,a,c}` / `{d,a,aa,f,e}` tree shape the app expects.
- Target entity: look up the EXISTING county municipality (`schema('treasury').from('municipalities')`, `eq('state', state)`, `eq('entity_type','county')`, `ilike('name', entityName)`, `.maybeSingle()` — the `seedCountyLinks.js:92-99` pattern). If not found → `console.error` + `process.exit(1)` (it must already exist from Phase 54). Do NOT call `treasury_ensure_municipality` with a population (it would clobber).
- Population (D-06): if a fetched row carries `estimated_population`, capture the max per year and backfill the entity ONLY where its population is null/0 (the `bulkLoadStateController.js:112-120` `.or('population.is.null,population.eq.0')` pattern, with `population_year`). If the feed has no `estimated_population`, use `--population` and apply it the same backfill-only way; if neither is available, warn loudly that per-capita will be 0 and continue.
- Never-overwrite pre-pass: before each write, look up an existing budget row for (entity id, fy, dataset_type); if it exists with a DIFFERENT `data_source` than this run's label, SKIP + log and do not write (mirror `bulkLoadStateController.js:findConflictingBudget`).
- Write: `supabase.rpc('treasury_sync_city_budget', { p_municipality_id, p_fiscal_year, p_dataset_type, p_total, p_tree, p_row_count, p_data_source_name: <label>, p_source_url: <pageUrl>, p_source_date: <fetchDate> })`.
- `--dry-run`: print categories/subcategories/total + top-5 + the population decision + any SKIP lines; perform ZERO writes.
- Env + client setup identical to the existing loaders (`SUPABASE_URL`, `SUPABASE_SERVICE_KEY`/`SERVICE_ROLE_KEY`; exit 1 if key missing). Header comment documents usage + that it generalizes the LA loaders (D-07) and is the runbook Step 5 tool.
</action>
