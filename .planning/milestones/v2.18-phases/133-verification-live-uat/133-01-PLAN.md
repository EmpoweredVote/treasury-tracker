# Plan 133-01 — PIMA-07: blind re-derivation + source-chain audit + loader confirmation

**Mode:** standard
**Goal:** Prove every *displayed* figure for the four Pima municipalities is real and durably sourced by re-extracting it from the source ACFR PDFs along a second, fully independent path and diffing against live production — the higher bar over Phase 132's DB-vs-RECON re-sum. This plan delivers the machine-verifiable core of PIMA-07: a from-scratch re-derivation harness (44 FY×mode, full tree, $0), a full source-chain audit, and confirmation that the Phase-132 loader source-safety invariants are in place and survive an idempotent, residue-free re-run.

This is the direct scaled analog of the shipped `verify-phase130-*.mjs` harnesses (Tucson, 1 city → 20 rows). Here it is 4 cities → 44 rows. Reuse those scripts' env-loading + `createClient` on the `treasury` schema + own-`pdftotext` + exact-0-exit conventions.

**D-05 status note (deviation from a naive "fix inline" reading):** the source-safe invariants were built into `scripts/processPimaCities.js` during Phase 132 (source-safe RPC, ephemeral `data_sources` create/delete, muni-keyed pre-load delete — confirmed in the 132-02 SUMMARY and by inspection). This plan therefore **confirms** them (code inspection + `node --check` + idempotent smoke-run) rather than re-applying. If inspection finds any invariant absent or wrong, Task 133-01-04 escalates to fixing it — the only branch that edits the loader.

<threat_model>
**T-133-01 — Privileged idempotent re-run of the production loader during the D-05 smoke-check.**
- *Surface:* Task 133-01-04 re-invokes `scripts/processPimaCities.js` with `SUPABASE_SERVICE_KEY` against the shared production `treasury.budgets` / `treasury.data_sources` tables for four municipalities.
- *Threats:* (a) a non-idempotent re-run mutating shipped figures; (b) leaving `data_sources` residue if the run aborts partway; (c) running against a wrong/expanded FY window (e.g. accidentally attempting the South Tucson FY2023/24 holes).
- *Mitigations:* the re-run is expected to net **0 change** (the RPC's `(municipality_id, fiscal_year, dataset_type)` upsert + muni-keyed pre-clear are idempotent); scope strictly to the existing windows (OV/Marana/Sahuarita FY2019–2024, South Tucson FY2019–2022 — no new FYs); re-run the D-04 source-chain audit immediately after and require 0 residue + all 44 rows still tie. The re-derivation and audit scripts are **read-only** against the DB (SELECT + a client-side HTTP HEAD/GET of each source_url). The loader hits WAF-blocked origins via mirrors and a sometimes-flaky Supabase path — a transient per-FY network timeout is a retry, not a residue failure (the ephemeral-cleanup lifecycle makes a re-run safe).
- *Block on:* high — any non-zero delta or new residue after the re-run is a blocker, not a warning.
</threat_model>
