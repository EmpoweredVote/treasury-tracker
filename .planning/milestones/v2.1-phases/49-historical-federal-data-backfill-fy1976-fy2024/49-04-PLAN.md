# Plan 49-04 — Receipts-lens backfill loader (build + dry-run verify)

**Mode:** standard
**Goal:** Build the historical receipts-by-source lens. The existing FY2025 `revenue` tree
is MTS Table 9 (API, FY2015+ only). History must come from **OMB Hist 2.1** (covers 1934→present).
CONTEXT D-04 chose a **flat 7-bucket** shape — one clean, citizen-legible level of "where the
money comes from." This is a NEW extractor + loader (no historical receipts loader exists).

**Real writes deferred to 49-05.**

<threat_model>
**T-49-02 — Wrong-year or mis-sourced data (shared).**
- *Receipts-specific threats:* (a) picking the wrong column/row for a year in a wide 1934→present table; (b) units mis-read (Hist 2.1 is in millions); (c) a bucket label drift across decades silently mismapped.
- *Mitigations:* read units from the file's line-2 text (never assume), locate columns by header TEXT, select the year row by exact 4-digit match (TQ by its explicit label), assert the 7 buckets sum to the Hist 1.1 receipts anchor within tolerance before writing, persist the resolved Hist 2.1 xlsx URL as source_url.
- *Block on:* high.
</threat_model>

## Tasks

<task id="49-04-01" type="execute">
<action>
Create `scripts/extractOMBReceipts.py` modeled on `extractOMBHistorical.py`: usage `python extractOMBReceipts.py <hist02z1.xlsx> <year-or-TQ>`. Read units from line 2 (millions), locate the 7 source columns by header text — "Individual Income Taxes", "Corporation Income Taxes", "Social Insurance and Retirement Receipts", "Excise Taxes", "Estate and Gift Taxes", "Customs Duties", "Miscellaneous Receipts" — plus "Total Receipts" for the cross-check. Select the requested year's row (exact 4-digit match; for `TQ`, the row whose first cell is the transition-quarter label). Emit JSON `{ "year": ..., "buckets": [{name, amount_dollars}], "total_receipts": ... }` with amounts normalized to dollars. Halt if any of the 7 labels is missing (layout drift) or the 7 buckets don't sum to Total Receipts within 0.5%.
</action>
