# Plan 49-01 — Transition Quarter storage primitive

**Mode:** standard
**Goal:** Make the schema able to hold the FY1976 Transition Quarter as a distinct,
labeled period without breaking the one-row-per-(entity,year,lens) invariant — so the
three loader plans can write TQ rows in Plan 49-05.

This is the **only** schema change in the phase and the **only** human-gated step. It is
deliberately small and backward-compatible (additive column + index widen + optional RPC arg).

<threat_model>
**T-49-01 — Shared-table migration corrupts or weakens existing data integrity.**
- *Surface:* `treasury.budgets` is app-facing (read by treasurytracker.empowered.vote) and the RPC is the shared write path for city/state/federal trees.
- *Threats:* (a) widening the unique index could silently allow duplicate NULL-label rows, regressing the dedup guarantee; (b) editing the RPC could break existing city/state loaders; (c) applying to production without review.
- *Mitigations:* use `NULLS NOT DISTINCT` so two NULL-label rows still collide (guarantee preserved); add `p_period_label` with `DEFAULT NULL` so every existing caller is byte-for-byte unaffected; **human checkpoint before apply**; verify with a post-migration probe that an existing FY2025 row is untouched and that a duplicate-NULL insert still fails.
- *Block on:* high. Do not apply without the GO checkpoint.
</threat_model>
