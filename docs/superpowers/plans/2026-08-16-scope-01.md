# SCOPE-01 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax. **This repo executes inline — no research/roadmapper subagents** (auto-memory `feedback_no_research_subagents`).

**Goal:** Record, for every row in `treasury.budgets`, which funds the figure covers — or an honest `unknown` — so the app stops silently comparing General Fund figures against all-funds figures.

**Architecture:** A `fund_scope` column on `treasury.budgets`, populated by a source→scope registry in which every entry carries the document it was reconciled against. Classification attaches to the **data source**, never to a row, and a source with no reconciliation stays `unknown`. Three harnesses prove coverage, prove no figure moved, and detect scope seams. Purely additive: no index change, no figure change, nothing that can break what works today.

**Tech Stack:** Node ESM (`.mjs`) · Supabase Postgres (`treasury` schema, shared with EV-Accounts) · vitest (`tests/**/*.test.mjs`)

**Spec:** `docs/superpowers/specs/2026-08-16-scope-01-design.md`

## Global Constraints

- **THIS MILESTONE CHANGES NO FIGURE.** `total_budget`, category and line-item values are byte-identical before and after. One new column, populated. Task 8 proves it.
- **`fund_scope` lives on `treasury.budgets`**, not on categories or line items. Scope is a property of the source, and `data_source` is on `budgets`.
- **Classification is per SOURCE, never per row.** A source has one scope by construction.
- **No source is classified without a reconciliation against an independent document.** Not by category names, not by the source's own title, not by plausibility. Unverified → `unknown`.
- **`unknown` is a correct outcome.** Ending with hundreds of unclassified rows is the milestone working, not falling short.
- **DO NOT widen the unique index.** The spec originally put `fund_scope` into `idx_budget_municipality_year_type`. That is deferred to SCOPE-02: nothing creates a second-scope row until then, so widening now opens the double-count hazard with zero benefit. SCOPE-01 stays strictly additive.
- **Values are `general_fund` · `total_governmental` · `all_funds` · `special_revenue` · `unknown`.** Enforced by a CHECK constraint; default `'unknown'` so a loader that has not been taught about scope produces an honest unknown rather than a silent wrong.
- **`special_revenue` was added after Task 1** (Chris, 2026-08-17). MA DLS Schedule A is 1,560 rows across 336 towns of Special Revenue Funds — a fund type that is not the General Fund, not the total of governmental funds, and not all funds, so none of the four original values described it. See `SCOPE-01-RECON.md` §1.4. **It is excluded from cross-entity comparison exactly as `unknown` is**, so the Task 10 Step 4 filter is over TWO values — never write it as `!== 'unknown'`.
- **The database is SHARED with EV-Accounts** (Express/TypeScript, `C:\EV-Accounts`, `accounts-api.empowered.vote`). Its treasury queries use explicit column lists over `pool.query()` — **not PostgREST** — so a new column is invisible to the API until that repo edits its SELECTs. Coupling is read-path only, so this plan lands first and safely; the API phase follows (Task 9).
- **No `scripts/lib/*.mjs` may start with `#!`** — the guard covers any module a test imports, wherever it lives (commit `40aa706`).
- **DB changes go through `mcp__supabase-local__apply_migration`**, verified with `execute_sql` (auto-memory `feedback_supabase_migration_mcp`).
- **`npm run lint` is excluded** from every gate — broken in this repo, has never exited 0.
- **Free sources, $0 API spend, executed inline.**

## Task 2: The registry and its matcher

**Files:** Create `scripts/lib/fundScope.mjs`, `scripts/data/fundScopeRegistry.mjs`, `tests/fundScope.test.mjs`

**Interfaces:**
- Produces `SCOPE = { GENERAL_FUND, TOTAL_GOVERNMENTAL, ALL_FUNDS, UNKNOWN }`
- Produces `classify(dataSource, registry) -> { scope, entryId }`
- Registry entry: `{ id, match: RegExp, scope, evidence: { document, figures } | null }`

- [ ] **Step 1: Write the failing tests**

```javascript
// tests/fundScope.test.mjs
import { describe, it, expect } from 'vitest';
import { classify, SCOPE, validateRegistry } from '../scripts/lib/fundScope.mjs';

// NOTE: the pattern is ANCHORED to the exact string. An earlier draft of this plan
// used /^CA State Controller/i, which also claims the 7,682 publicpay.ca.gov
// salaries rows the Modesto reconciliation never covered. See RECON §1.3.
const reg = [
  { id: 'ca-sco-city-exp', match: /^CA State Controller - Expenditures$/, scope: SCOPE.ALL_FUNDS,
    evidence: { document: 'Modesto FY2024 ACFR', figures: '291,641,122 + 296,400,946 = 588,042,068' } },
  { id: 'no-evidence', match: /^Plausible Source/i, scope: SCOPE.GENERAL_FUND, evidence: null },
];

describe('classify', () => {
  it('matches a source to its registered scope', () => {
    expect(classify('CA State Controller - Expenditures', reg))
      .toEqual({ scope: SCOPE.ALL_FUNDS, entryId: 'ca-sco-city-exp' });
  });

  it('does NOT let the CA SCO entry claim the publicpay salaries source', () => {
    // Same office, same prefix, unrelated program, different dataset_type, and
    // NOT covered by the Modesto reconciliation. The regression test for RECON §1.3.
    expect(classify('CA State Controller — Government Compensation in California (publicpay.ca.gov)', reg))
      .toEqual({ scope: SCOPE.UNKNOWN, entryId: null });
  });

  it('returns unknown for a source no entry matches', () => {
    expect(classify('Some New Loader FY2027', reg))
      .toEqual({ scope: SCOPE.UNKNOWN, entryId: null });
  });

  it('REFUSES to classify from an entry with no evidence', () => {
    // The safety property. An entry that asserts a scope without a reconciliation
    // is exactly the guess this milestone exists to prevent, so it classifies
    // as unknown no matter what its `scope` field claims.
    expect(classify('Plausible Source 2024', reg))
      .toEqual({ scope: SCOPE.UNKNOWN, entryId: null });
  });

  it('returns unknown for null/empty data_source rather than throwing', () => {
    expect(classify(null, reg).scope).toBe(SCOPE.UNKNOWN);
    expect(classify('', reg).scope).toBe(SCOPE.UNKNOWN);
  });

  it('takes the FIRST matching entry so precedence is explicit', () => {
    const overlapping = [
      { id: 'specific', match: /^CA State Controller - Revenues/i, scope: SCOPE.ALL_FUNDS, evidence: { document: 'd', figures: 'f' } },
      { id: 'general', match: /^CA State Controller/i, scope: SCOPE.ALL_FUNDS, evidence: { document: 'd', figures: 'f' } },
    ];
    expect(classify('CA State Controller - Revenues', overlapping).entryId).toBe('specific');
  });
});

describe('validateRegistry', () => {
  it('rejects an entry claiming a scope with no evidence', () => {
    const r = validateRegistry(reg);
    expect(r.ok).toBe(false);
    expect(r.unevidenced).toEqual(['no-evidence']);
  });

  it('accepts a registry where every non-unknown entry is evidenced', () => {
    expect(validateRegistry([reg[0]]).ok).toBe(true);
  });

  it('rejects duplicate entry ids', () => {
    const dup = [reg[0], { ...reg[0] }];
    expect(validateRegistry(dup).ok).toBe(false);
  });
});
```

- [ ] **Step 2: Run and watch them fail**

## Task 4: Per-source reconciliation

**The evidence-gathering task, and the bulk of the milestone.** Each source gets ONE reconciliation against an independent document, in the shape that settled CA SCO.

**Files:** Modify `scripts/data/fundScopeRegistry.mjs`, `docs/superpowers/plans/SCOPE-01-RECON.md`

**The method, per source:**
1. Pick one entity where an independent document exists (an ACFR, ideally one already in `docs/`).
2. Extract the document's own General Fund and Total Governmental figures for one year.
3. Compare against the stored row's total for that (entity, fy, dataset).
4. Whichever matches, that is the source's scope. **If none matches, the source stays `unknown`** and the mismatch is written up — that is a finding, not a failure.
5. Record in the recon doc: entity, year, document, all figures, and which matched.

| Source | Suggested probe entity | Expectation (do not assume) |
|---|---|---|
| CA State Controller | **DONE** — Modesto FY2024 | `all_funds`, reconciled to the dollar |
| WA SAO | Tacoma or Seattle (ACFRs already in `docs/`) | `general_fund` |
| MA DLS | any `"— MA General Fund"` city | `general_fund` — the string self-describes, which is a hint and not evidence |
| VA APA Comparative Report | Alexandria or Falls Church | unknown |
| MN OSA | any MN city with a fetchable ACFR | unknown |
| Ohio AOS | Columbus | unknown |
| Transparent Utah | Salt Lake City | unknown |
| Oregon city ACFRs / Tucson / Pima | Bend (already loaded, GF-only by its loader header) | `general_fund` |
| CA city documents | Anaheim | `general_fund` |
| LA City / SF / San Diego own-source | LA City | likely `all_funds` — its seam was only −4.8% |
| State-level ACFR rows | one state | `general_fund` |

- [ ] **Per source, Step 1: Reconcile** — the five-step method above.
- [ ] **Per source, Step 2: Write the registry entry** — `id`, `match`, `scope`, `evidence` with the document and the figures that matched. No evidence, no entry.
- [ ] **Per source, Step 3: Record in the recon document** — including sources that came out `unknown` and why.
- [ ] **Per source, Step 4: Commit** — one commit per source, so a wrong classification is revertible alone.

⚠ **Do not batch these.** A source classified in a batch is a source classified by momentum.
